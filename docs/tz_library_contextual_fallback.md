# Контекстный fallback из библиотечного пака — отложенное расширение

Статус: **отложено пользователем 2026-10-13**. Идея сохранена для отдельной
проработки; механизм не входит в текущие 4d/L-5 и не является зависимостью
их завершения. Исходное предложение — `tz_template_library_packs.md` §5.1
и план `library-packs-model.md` §5c.

## Базовый действующий контракт

Дефолты определяются внутри POJO и объявленными дефолтными библиотеками
движка. Домен определяет, допускается ли fallback, или требуется отказ.
Отложенное расширение этот контракт не заменяет.

## Идея расширения

Автор библиотечного пака может предложить своего члена как контекстный
fallback. Это дополнительное назначение в manifest обычного пака,
а не объявление пака дефолтной библиотекой движка. Оно само по себе
не делает пак доступным миру и не даёт гарантию покрытия всех случаев.

Прежняя схема `world → pack → POJO`, «первый найденный», не принимается
как готовый универсальный алгоритм. При битой ссылке исходный пак может
быть неизвестен, а предложенное тело может не подходить для требуемого
назначения, размеров или иных доменных ограничений.

## Что определить до реализации

- Ситуации, в которых разрешено использовать подстановку пака; отдельно
  разобрать пустую ссылку, неизвестный UID, недоступного владельца и битое тело.
- Источник контекста и выбор пака, если происхождение ссылки неизвестно.
- Доменные критерии пригодности подстановки и границы её покрытия.
- Поведение, когда подстановка отсутствует или непригодна: действующий
  доменный default либо отказ; универсальное правило пока не задано.
- Необходимость world override, приоритеты нескольких предложений и диагностику.
- Формат metadata, идентичность ссылки и её перенос при copy/remap;
  SQL-хранение и семантику import/export только после определения поведения.

## Текущее состояние кода и границы

`LibraryArchiveManifest.defaults` уже существует. Поле остаётся в codec
для транспортной совместимости; его наличие не активирует fallback,
не означает готового SQL round-trip и не требует добавлять SQL-поле
или runtime resolver в 4d/L-5.

Поведение импорта непустого отложенного поля должно быть явным, без обещания
его применения или молчаливой потери. Конкретный ответ consumer определяется
при подключении архивного импорта; из этого не следует требование реализовать
всё расширение. Код текущим решением не меняет обработку входных данных.
