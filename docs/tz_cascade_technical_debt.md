# Возможный техдолг каскада

## CASCADE-TD-1 — восстановление контекста отдельно загруженной локации

**Статус:** вероятный техдолг; необходимость реализации не подтверждена.
Зафиксирован 2026-10-07. Уточнить при реализации patch/patch rollback
и при типизации DAG. Самостоятельную реализацию parent-resolver не начинать
без подтверждённого caller-контракта.

Сейчас генераторы передают resolved-контекст сверху вниз через scope-helpers
и `extend()`. Общего восстановления контекста по `parent_location_uid` нет.
Чтение сохранённой локации и текущий экспорт не требуют такого механизма.

### Что проверить при реализации patch и rollback

- Если патч сохраняет полное прежнее состояние, rollback восстанавливает
  данные напрямую; каскад не пересчитывается.
- Если производные данные восстанавливаются повторной генерацией,
  определить источники контекста: сохранённый snapshot, контекст caller'а
  или загрузка предков. Только последний вариант может требовать parent-resolver.
- Для точного воспроизведения определить, какие исторические значения
  предков, seed, шаблоны и версии генерации нужны и где они сохраняются.
  Обход текущих родителей сам по себе не гарантирует точный rollback.

### Что проверить при типизации DAG

- Получает ли узел необходимый typed/resolved-контекст явным входом
  или стартует с одной локацией/UID без верхнего контекста.
- Достаточны ли сохранённые stamped-параметры и шаблонные входы;
  требуется ли вообще повторный cascade resolve.
- Если данных недостаточно, закрепить ответственность за их загрузку
  на caller-границе, прежде чем выбирать механизм восстановления.

### Инварианты возможного решения

- Parent-цепочка находит source-объекты; порядок и приоритет каскада
  остаются в `CascadeLink.above/below`, независимо от DAG.
- Отсутствующие объекты не удаляют объявленные промежуточные домены;
  EmptyLink сохраняет свой контракт.
- Определить обработку нескольких предков одного scope и получение
  шаблонных источников: одних NL и payload_kind может быть недостаточно.
- Не добавлять повторный materialize/RNG, если достаточно сохранённых
  результатов или уже переданного контекста.

**Критерий уточнения:** при реализации patch/rollback и типизации DAG
зафиксировать реальные точки входа и доступные данные; подтвердить необходимость
отдельным согласованным планом либо закрыть пункт как ненужный с обоснованием.
Создание synthetic NL над масками и назначение semantic parent при placement
остаются отдельной задачей и из этого пункта не следуют.
