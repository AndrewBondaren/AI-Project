Прочитай [план](../plans/error-contracts-1.md), §6.1 и записи R-J3b/R-J3c, и [правила code review](../rules/review-split.mdc). Зафиксируй текущий HEAD и относящиеся к J3 рабочие изменения. Для каждого замечания сопоставь контракт, актуальную строку кода и адресный тест. Различай исправление, принятое решение о поведении и передачу ответственности в J4.

Проверь в J3b index/validate, connectionGraph и preflight; в J3c общий mapper, wire loc, carrier, неизменяемость отчёта и обработку одноразового iterable. Начни с существующих тестов backend/tests/errorContracts, затем запусти недостающие адресные сценарии. Принятый EC-11 используй как вход. Повторяй его проверки только для затронутого после приёмки пути.

Выдай таблицу «ID → вердикт → файл:строка → проверка», затем отдельный вывод о готовности J3b и J3c и точный остаток для J4. Укажи непроверенное. Только ревью, без изменений файлов и коммитов.
