# PA-1: фактические границы Pack / Artifacts

2026-11-18. Статическая трассировка кода и callers. Результат исследования для PA-2, не приёмка целевого API и не evidence runtime. Код не менялся, тесты не запускались. Основание: PA-1…PA-5 в world-pack-v2-single-manifest-contract.md и обязательные критерии dag-generator-interface.mdc.

## Скоуп и критерий доказательства

Проверены imports Artifacts/Publication и вызовы в backend/app/application/worldData/pack, связанные backend/app/db/repositories/sqlite/worldPack, storage/artifacts/manifestBlobBackend.py, core/container/packs.py и callers в backend/app и backend/tests. Поиск включает имена функций/классов, не только constructors. Наличие файла в app не доказывает production-подключение. Отсутствие найденного caller не доказывает невозможности динамического подключения; ниже сообщаются результаты статического поиска.

Все пути далее относительно backend/app. Для каждого runtime-перехода PA-2 должен предъявить exact public class/interface/signature, input/output/errors и ответственность; таблица не изобретает отсутствующие API.

## Вывод PA-1 и передача PA-2

Прямые Artifacts calls в Pack существуют. Однако ранее сказанное о production-подключении всей новой цепочки было слишком широким: оно подтверждено для регистрации форматов, но не для finish_pack_preparation, StagedClimateFields, PinnedManifestReader и связанного нового pinned read маршрута. Старый WorldPackWriter/WorldPackReader подключён отдельно через PacksWiring; это legacy cutover scope, не доказательство использования новой цепочки.

PA-1 выполнен как статическая инвентаризация перечисленного скоупа. Независимая приёмка не проводилась. Незакрытые решения передаются в PA-2:

1. Точный публичный обмен Pack bytes → Artifacts prepare/stage → результат Pack, без закрепления ещё не принятых новых имён Pack методов.
2. Public bounded verified read и authority/lifetime: сохранение защиты при pin close/cancel/GC, на cold и cache-hit маршрутах. Одного descriptor/holder POJO недостаточно считать право проверенным.
3. Владелец и public completion API, exact candidate replay, полный retention/adoption; concrete internal bindings отдельно от public операций. Stage не READY.
4. Перенос semantic decode из storage callbacks в Pack-owned preparation/admission согласно предложению Artifacts; budgets/errors не теряются.
5. Сопоставление принятого runtime-порядка с конкретным разделением public prepare. Нельзя реализовать split под видом рефакторинга до согласования контракта.

Исполнение PA-2 не меняет генераторы, не создаёт DAG-ноды и не назначает версии. Реальные интеграционные гарантии проверяются позднее в PA-4/PA-5; статический trace их не заменяет.
