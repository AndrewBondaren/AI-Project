Fault и cancellation порождают по одной попытке записи с источником входной проекции. Bare raise сохраняет объект исключения. При сбое emitter, включая CancelledError, caller получает прежний результат либо исходное исключение проектора. Ошибка validator после проекции не создаёт Time fault.

## Сравнение по §6.3

Независимая приёмка от 8 ноября 2026. Через обе штатные фабрики успешный calendar update вызвал project один раз, смена часов для двух календарей без replacements — два раза. Те же количества получены с candidate.py из 0d4260b3. На рабочей версии успех дал ноль попыток emit.

Для каждого из пяти подставленных отказов обе подготовки вызвали project один раз и сформировали один PROJECT WARNING с ожидаемым кодом. Бюджетный отказ сохранил идентичность, CalendarInvalid сохранил issues, остальные три исхода вернули прежний SettingsInvalid по capture. На настоящем проекторе воспроизведены отказ по бюджету и недопустимый selected. При RuntimeError и CancelledError проектора получена одна запись PROJECT и проброшен тот же экземпляр исключения. При TypeError или CancelledError внутри emit проверены одна попытка и сохранение каждого первичного исхода.

В отдельной пробе через обе фабрики исключение resolve_at дало ноль вызовов project и emit, исключение валидатора после успешной проекции — ноль emit. При смене часов явный origin первого календаря пропустил его проекцию. При отсутствии replacement локальный origin=None восстановился из проекции. Подстановка бюджетного отказа для второго календаря вернула именно этот отказ и дала одну попытку emit в обоих случаях. Порядок вызовов project совпал с порядком записей, требовавших проекции.
