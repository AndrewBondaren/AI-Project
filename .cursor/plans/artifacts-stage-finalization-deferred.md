## 3. Trace и граница отдельной поставки

### Итог Q2 и владельцы оставшихся проверок — 2026-11-27

Локальная спецификация Q2/DF-02 предъявлена Artifacts; статус PROPOSED / OPEN, не архитектурный PASS и не разрешение реализации. Подробная таблица состояний, методы и predicates приведены ниже. Итог: authoritative отсутствие full acquisition не требует release; full acquisition без link допускает только full release после confirmed prohibition и доказанного no-dispatch; committed reserve без link сохраняет catalog/reservation и все holds; committed link требует DF-01 evidence, exact own-temp cleanup и atomic local/full release. Unknown commit требует reconciliation exact identity, matching committed release даёт идемпотентный no-op после integrity checks.

Отсутствие link до его создания — lawful состояние, не corruption. Само по себе оно не доказывает отсутствие effects. No-dispatch выводится только из confirmed prohibition, authoritative отсутствия link, atomic local acquisition/link, обязательного committed link перед каждым physical dispatch и проверки prohibition/release в UOW reserve/local acquisition. Reserve/hold effects этим выводом не отрицаются. Synthetic local acquire, reopening admission и удаление чужих/shared holds запрещены; нового механизма хранения не вводится.

### Q2 / DF-02 — уточнение owning proposal, 2026-11-27

Статус: PROPOSED, не accepted и не реализовано. Этот раздел уточняет прежний RC-03 `INSUFFICIENT_EVIDENCE` для no-link в owning resolution; исходный evidence-документ и соседние планы не изменяются. DF-02 остаётся OPEN до проверки predicates и согласования затронутого scoped catalog/drain контракта координатором и пользователем. DF-01 не закрывается. Ниже рассматривается только target этапа 2; перенос вывода на legacy backend-owned local acquisition запрещён.

Обозначения: K = (operation_id, stage_id, generation, claim_id) из immutable binding и exact acquisition; A — StageAcquisitionRow; R — catalog identity и exact reservation/operation hold facts, а не новая reservation row; L — existing local acquired event вместе с StageLocalClaimLinkRow; P — StageEffectProhibitionRow; X — StageReleaseRow; C — completion. Facts читаются согласованно, включая цепочки existing local releases. R может существовать до данной execution и быть общим для нескольких stages: наличие R не устанавливает его исключительное владение K. Ни отсутствие L, ни отсутствие C, ни пустой temp namespace сами по себе не доказывают отсутствие effects.

**Конкретная минимальная дельта методов (всё ниже — proposal).**

- `SqliteStageAttemptStore.reserve_stage(claim: StageWriteClaim) -> StagingReservation`: новый внутренний SQL-only wrapper. В одном existing write UOW проверяет exact A/current WRITE authority/отсутствие P и X, затем вызывает `SqliteArtifactCatalog.reserve_in_scope(scope: CommitScope, lease: OperationLeaseRef, descriptor: ArtifactRef) -> StagingReservation`. Последний — предлагаемый scoped extraction existing `reserve`, сохраняющий его catalog/hold predicates, без собственного commit. Lease и descriptor берутся из K/binding. Existing legacy `reserve(lease, descriptor)` сохраняется; target writer вызывает только `reserve_stage`. Отдельный precheck перед existing independently committing reserve недостаточен: он допускает reserve после P/X.
- `local_writer(claim, reservation)` в одном UOW проверяет A, exact R и current writable authority, отсутствие P/X, затем атомарно пишет local acquired event + L. Ни handle, ни dispatch до confirmed commit. Отсутствие link у чужой/legacy local acquisition не исправляется: она остаётся отдельным blocker operation drain.
- `inspect_finalization(request)` выдаёт FINALIZE view exact A также без R/L; view не создаёт local claim. Lookup не даёт разрешения на cleanup/release. Already matching X возвращает finalized после integrity checks; отсутствие A не создаёт execution. Unknown lookup не преобразуется в missing.
- `prohibit_effects_in_scope(scope, claim, guard)` принимает lawful no-R/no-L, проверяет binding/A и атомарно вставляет либо подтверждает exact P, перечитывая R/L/X. Link обязателен только там, где он уже должен существовать по atomic local acquisition. Несовпадение существующего link — invariant fault. Wrapper `prohibit_effects` возвращается только после confirmed commit; потеря ACK требует нового authoritative чтения.
- `release_finalized_in_scope(scope, claim, guard)` имеет две явные ветви. NO_LOCAL: exact A+P, нет X, authoritative L отсутствует, доказан описанный ниже no-dispatch predicate — пишет только X. LINKED: exact A+P+L, доказан DF-01 drain и завершён exact cleanup — existing local release и X одним commit. Matching X — no-op; mismatched/partial release chain — fault, не компенсация. Ни одна ветвь не удаляет reservation/catalog/operation holds и не создаёт C. Job перед вызовом обеспечивает evidence; SQL store не выдумывает physical proof из guard.

Все reserve/local/P/X transitions сериализованы одним existing transaction graph. `assert_effect_allowed(claim, guard)` для WRITE/VERIFY требует confirmed A+R+L, exact live local event, отсутствие P/X и writable authority; каждый physical batch удерживает тот же gate от проверки до завершения. Seal повторяет predicates в atomic seal/C UOW. Никаких dispatch из reserve, local acquisition, context exits или безусловного finally. Новый scoped reserve — междоменная по transaction semantics дельта для адресного согласования, а не принятый API.

**Полная таблица crash boundaries.** В таблице N означает путь `inspect → resolve exact target/gate → prohibit → confirmed reread → NO_LOCAL release`; D означает `inspect → same gate → prohibit → DF-01 evidence → exact own-temp cleanup → LINKED release`. SQL scopes закрыты до ожидания OS gate. В D отсутствие process-loss evidence даёт `Unresolved(EFFECTS_NOT_QUIESCENT)` без cleanup/release. Gate сам не evidence. Ошибка registry/gate или unknown SQL останавливает обе ветви без dependent effects.

**No-dispatch predicate и committed reserve без link.** `NO_LOCAL(K)` означает: coherent authoritative A; confirmed P; confirmed absence X/L; все target local acquisitions создают link атомарно; любой physical effect K требует этого committed link; link/acquisition history не удаляется; reserve и local admission проверяют P/X в той же serialization boundary, что их запись. После P link не может возникнуть, а до P его отсутствие исключает прохождение обязательного dispatch prerequisite. Это доказательство отсутствия *physical effects K*, а не отсутствия R/holds или effects других executions. Если хотя бы один caller обходит prerequisite либо history неполна — `INSUFFICIENT_EVIDENCE`, claims остаются pending. Already committed reserve оставляется как есть: finalization освобождает claim, а lifecycle owner позже решает судьбу exact operation holds по общему drain predicate. Никакого удаления «своего на вид» hold по artifact_id.

Гонка reserve/local против finalization: если reserve выиграл UOW, P увидит R; если P выиграл, reserve_stage откажет до catalog mutation. Если local выиграл, P увидит L и выберет D; если P выиграл, local_writer не создаст ни event, ни link. Snapshot из inspect до gate нельзя использовать для выбора N: выбор повторяется под authority UOW после fencing. Current closed/stale admission не требуется для finalization старой K и не переоткрывается.

**Unknown и повтор.** Unknown — состояние знания caller, не новая durable row/status. После `UnknownCommitOutcome` используется existing quarantine/reconciliation; зависимые dispatch/cleanup/release прекращаются. Чтение на здоровой authoritative connection должно установить завершённый исход транзакции, а не просто отсутствие строки в старом snapshot. A/R/L/P/X сверяются по сохранённой exact identity; новый claim_id/generation не выделяется. Unknown P запрещает cleanup и release до confirmed P; unknown X запрещает сообщать finalized до matching X. Если X отсутствует, replay повторяет весь evidence path. Concurrent finalizers под одним gate повторяют persisted checks: второй при matching X не делает физическую работу. Unknown нельзя выдавать за refusal/rollback; malformed present facts — infrastructure invariant fault, lawful missing R/L до их создания — не corruption.

**Критерии проверки (до PASS).** Fault injection до/после каждого commit и ACK каждой строки таблицы; crash до/после local handoff и каждого physical batch; две connections для обоих исходов reserve/P и local/P races. Проверить: ноль dispatch без confirmed L; P-first даёт ноль новых reserve/local writes; local-first всегда D; R-without-L завершает только full claim и сохраняет каждый hold; stale/closed execution проходит N без writable acquire; link-present без DF-01 evidence не release; unknown любого commit не создаёт новую identity; повтор после X имеет ноль cleanup/release writes; cleanup crash повторяет evidence; foreign/shared holds и legacy local-only claims сохраняются; operation drain учитывает все оставшиеся claims. Проверить все affected callers и общий UOW, а не только happy-path тест. Тесты не заменяют отсутствующую DF-01 гарантию primitive.

Нового журнала, таблицы reservation, dispatch marker или persisted finalization state не требуется: используются уже предложенные A/L/P/X и existing catalog/holds. NO_LOCAL выводится только из атомарности, fencing и обязательного dispatch prerequisite. Для linked состояния этот вывод неприменим; новый механизм хранения ради его искусственного закрытия не вводится. Междоменная приёмка scoped reserve/общего drain остаётся OPEN; пакет предъявлен пользователю для координаторской сверки, сообщения в другие чаты в этом проходе не отправлялись.

Предложенный этап-2 normal path: DAG → public stage → writer → full acquisition → reserve → local acquisition/link → authorized write/verify → atomic seal/completion → finish_live внутри обоих contexts → один release commit → context exits. DF-02/04 должны закрыть exception/cancellation ответвления до принятия этого trace.

Предложенный recovery path: DAG → public recover → internal recovery job → inspect → outcome либо internal finalizer → atomic finish/recheck → owning result → DAG. Точный dispatch задан Q3 ниже; branching следующего public CALL принадлежит DAG, backend алгоритм в ноды не переносится.

### Q3 / DF-03 — единая таблица recovery dispatch, 2026-11-27

Статус: контрактная дельта собственного плана, PROPOSED; DF-03 остаётся OPEN до координаторской сверки и решения пользователя. Код, чужие планы, public DTO и утверждённый порядок DAG не меняются. Раздел уточняет RC-CONSTRUCTION `inspect_recovery`/`finish_recovery`, сохраняя owning precedence и BF-01 из owning resolution. DF-01/02/04 и integration Q5/Q6 этим не закрываются. Пакет для координатора `Between domain operations` предъявляется через пользователя; разрешения на межчатовую рассылку нет.

Сигнатуры остаются: `inspect_recovery(StageRecoveryInput) -> StageAttemptResult | StageFinalizeInput`; `ArtifactStageFinalizer.finalize_execution(StageFinalizeInput) -> StageFinalizeResult`; `finish_recovery(StageRecoveryInput) -> StageAttemptResult`. Вход finish — исходный exact recovery request, не bool от job и не подменённая generation. K/A/R/L/P/X/C имеют смысл Q2. Таблица применяется сверху вниз: первая подходящая строка определяет единственную ветвь. Проверки integrity/binding обязательны и при replay; ошибки чтения не являются отсутствующими facts. «Outcome» завершает recover непосредственно, без finish. Только finalized либо уже подтверждённый release ведёт к finish; отсутствие release никогда не пропускается.

**Точное owning основание finalization.** Для строки 16 нужны exact persisted consumed execution A и immutable binding/generation без successor, отсутствие известного live owner и положительное evidence допустимого завершения его lifetime: подтверждённое прекращение owning runtime либо явная завершённая передача lifetime в owning composition. Простое «live owner не найден», elapsed timeout, exception stage, отсутствие completion или освобождённый OS lock таким evidence не являются. SQL store не производит runtime evidence: admission допустим лишь когда оно доступно и проверяемо через уже согласованный owning lifetime predicate; до спецификации его конкретного producer/lifetime по DF-01/04 применяется строка 15. Новый persisted status, takeover token или public evidence DTO этим предложением не вводится. FINALIZE view разрешает только exact завершение старой execution, не WRITE/VERIFY/seal. Допуск к job ещё НЕ proof безопасности cleanup/release: после gate и confirmed P finalizer повторно доказывает Q2 NO_LOCAL или completion всех submitted effects writer **и прежних finalizers**, включая cleanup. Unknown barrier оставляет claims/holds pending; gate/P сами drain не доказывают.

**Единственный finish / successor transition.** После `StageExecutionFinalized` job вызывает finish один раз для исходного request. В одном existing write UOW store заново проверяет integrity/exact binding и chain; applicable historical C имеет прежний приоритет; затем current operation fence, cancellation/admission; membership/current generation, consumption, уже записанный successor; exact full X и linked local release по owning predicate, отсутствие незавершённых effects и доказанную безопасность partial effects для повторной записи. P требуется там, где release произведён finalization path, но не подменяет release/evidence. Отсутствие C — только отсутствие success, не retry permission. Изменение facts после inspect обрабатывается теми же приоритетами таблицы: C → Confirmed, closed/cancel/stale → Refused, existing successor → exact replay/Unresolved; недостаточная quiescence → ATTEMPT_NOT_QUIESCENT, иная недостаточность safety evidence → INSUFFICIENT_EVIDENCE. Только если все predicates выполнены, atomic retire g + register единственного g+1 возвращает Allowed. UOW сериализован с close/consumption и конкурентным recover; retirement без регистрации successor и вторая выдача недопустимы. При lost ACK сначала reconciliation authoritative outcome, затем exact replay, без bump. X доказывает завершение execution, но сам не разрешает successor и не завершает operation.

**Ошибки и границы.** `ValidationError`, `StageBindingRejected`, invariant/corruption, registry/backend/OS/storage faults, `UnknownCommitOutcome` и cancellation проходят в исходной категории с cause/diagnostics; их нельзя превращать в Refused/Unresolved/Allowed или скрывать историческим success после ошибки чтения. Unresolved означает успешно установленную недостаточность evidence. Mapping finalizer `EFFECTS_NOT_QUIESCENT → ATTEMPT_NOT_QUIESCENT` сохраняет owning причину EFFECTS_NOT_QUIESCENT в diagnostic/cause transport; exact wire представление остаётся внешним OPEN Engine/Fields, а не новым молчаливым кодом. После успешного inspect disappearance A/g не нормальный `STAGE_UNTRACKED/GENERATION_UNTRACKED`: при запрете deletion это invariant fault; неизвестный read остаётся ошибкой. Cancellation/ошибка finalizer не запускает finish в finally; repeated cancellation/lifetime ACK остаётся DF-04. Unknown release/finish разрешается authoritative reconciliation, не повтором stage.

Recovery job владеет только последовательностью inspect → internal finalizer → finish и указанным mapping; не дублирует SQL policy, не acquires WRITE и не делает cleanup самостоятельно. Finalizer владеет exact backend resolution, gate/barrier, prohibition и cleanup/release lifetime; не выбирает successor/terminal. SQL store владеет coherent persisted facts, authority predicates и атомарным successor transition; не зависит от backend/gate/job, не ждёт IO и не изобретает physical/runtime evidence. Публичный service остаётся thin delegation. Ни один из них не запускает следующий stage, foreign public CALL или новую DAG ветку. Allowed возвращается DAG; Confirmed не превращает неизвестный старый child в фиктивный success. Публичные границы, сохранение категорий, lifetime и неизменный порядок должны пройти обязательную DAG-приёмку; данный раздел не объявляет её пройденной.
