# Pack / Source: актуальный статус после исправления DAG

**Итог текущей задачи:** пользователь уточнил «завершить контрактный план Pack», без реализации кода. Единая точка входа — [итоговый Pack scope](pack-contract-final-scope.md). Этот файл остаётся историей Source/DAG обмена, а не новым delivery-планом или перечнем блокеров Pack.

2026-11-14. Основание — [исправленный ответ DAG](dag-pack-source-binding-response-2026-11-14.md), передающий прямое указание пользователя. Прежний чеклист заменён: требования, выведенные из отозванных DAG-предложений, больше не действуют.

## Что сохраняется

- SourceFailure — единая owning ошибка Source; Pack не вызывает публичный Source API и не преобразует SourceFailure в свой diagnostic.
- [Локальная A3-проверка](pack-source-a3-reacceptance-2026-11-14.md): единый binding, metadata-коды и границы ошибок согласованы между Pack документами и ТЗ. Это не приёмка DAG binding или runtime.
- Owning [Pack exchange](pack-source-exchange-contract.md) описывает потребляемые данные; его привязка к конкретным нодам не считается принятой.
- PACK-METADATA-PLANNING остаётся разрешённой неблокирующей отсрочкой.
- [Publication response](pack-source-adoption-publication-response-2026-11-14.md) остаётся отдельным DESIGN OPEN. Предложения инфраструктуры не принимаются автоматически.

## Что отозвано

detailed_initialization описан только верхнеуровнево и к генераторам не прикреплён. Предложенные агентами phase/context/continuation, prepared L2/C11 связи, publication handoff, upper registrations, Source command variants и unsupported policy не являются основанием согласования или реализации. Выведенные из них A1/A2 gates текущего Pack сняты. Проверенные legacy DTO не объявляются требуемыми producers нового маршрута; их недостаточность не блокирует текущий Pack.

Удалённые дополнения DAG не используются и не заменяются новым агентским предложением. Состав нод, имена, контракты и связи определяются только вместе с пользователем; legacy-ноды использовать нельзя. Согласование между агентами не заменяет решение пользователя.

## Дальнейшие границы работы

Актуальное решение пользователя: Source, Snapshot и Cache доступны как зависимости; интеграция с DAG — последний шаг после завершения Pack. Приоритет имеет [итоговый scope](pack-contract-final-scope.md); прежние списки DAG gate не восстанавливать.

1. Продолжать независимые owning Pack задачи по принятому плану; не требовать заранее prepared L2/C11 или внешний continuation ещё не спроектированной ноды.
2. Конкретную привязку к DAG рассматривать отдельно вместе с пользователем. До этого не выдавать предложенные карточки/семь фаз за принятые bindings.
3. Внешние adoption/retention/replay требования согласовывать в собственном publication scope, без назначения неутверждённого DAG caller.
4. Код реализовывать через implement-plan только для принятого среза; приёмка кода — отдельный этап по правилам проекта.

Runtime не менялся. A3 сохраняется только в локальном объёме Pack POJO/diagnostics; прежние ссылки на неподтверждённые DAG связи не являются доказательством приёмки маршрута.
