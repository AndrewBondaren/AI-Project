# GEO-I9.3 — ревью исправления 01–96

**2026-11-04 · FAIL по полноте реестра.** Множества ID в таблице I9.3 и комментариях backend/app совпадают с диапазоном 01–96. Три замечания [ревью 01–89](geo-i9-3-legacy-registry-review-01-89.md) адресованы. Для river назначен один publisher, описаны metadata, входы, зависимости и проверки старого ключа. Для boundary adapter и climate provider указаны caller, типы и приёмка. При проверке смежных рёбер исправленного графа остались четыре замечания.

Пути отсчитываются от корня репозитория. Проверка статическая, вывод относится к реестру. Сценарии ниже предназначены для приёмки перехода.

1. **88/90/93 — support отвергает корректный native river.** В `backend/app/application/worldData/generators/terrain/relief/surfaceCoatingSupport.py:68–72` метод SurfaceSupportDependencies.require_coherent требует прямой relief.ref в river_relief.dependencies. Его вызывает facts перед построением support (:109–114). По новой таблице прямые зависимости river — fine_water и hydrology_routes. Проверка закономерно завершится ошибкой даже при полностью согласованном bundle. 88 описывает замену источника shore и типов, но не замену этого условия. Зафиксировать способ проверить согласованность используемого relief с native geometry через реальные upstream refs. Пройти зарегистрированную цепочку до support и coating с корректным native river, затем подменить только relief чужой ревизией и получить отказ.

2. **90/92/94 — в таблице зависимостей W не учтён prepared natural.** PreWaterTerrainWindowJob.prepare добавляет PREPARED_NATURAL=prepared.ref в W.dependencies (`backend/app/application/worldData/generators/terrain/planning/preWater/terrainWindowJob.py:49–54`). Native placement требует этот slot (`backend/app/application/worldData/generators/terrain/designedWater/preparation/nativePlacementDependencies.py:61–73`). GeoSurfacePlanBundle.coherent ищет ожидаемый ref для каждого upstream в собственной таблице (`backend/app/application/worldData/planning/contracts/surfacePlanBundle.py:87–102`). В 94 в таблицу предлагается добавить только W/F. Внести prepared natural в зарегистрированный граф и таблицу refs либо определить отдельный источник для проверки полного ожидаемого prepared.ref. Проверить admission bundle с подлинным W и отказ при отсутствующем или подменённом prepared.ref при тех же климате и terrain. Сам proof W уже описан в I5.1, пропущено его подключение к общей сборке.

3. **77/91/92/95 — источник boundary snapshot не доведён до registry.** Целевой snapshot требует PlanEnvelope[CanonicalOpenWaterSource]. В `backend/app/dataModel/surfacePlanning/surfacePlanBindings.py:86` прямые upstream границы — final и water placement. В `backend/app/application/worldData/planning/composition/surfacePlanningAssembler.py:125–131` prepare_geo передаёт ровно эти два envelope. Native final и canonical source имеют разные payload и ref. Строка 95 исправляет внутреннего потребителя уже созданного snapshot. Добавить к реестру получение canonical source для boundary, соответствующую декларацию зависимостей и передачу точного source.ref вместе с P2. Пройти coastline_boundaries через registry на холодном и прогретом кэше. Отклонить source с другим ref при неизменном P2. Эта проверка не зависит от формата хранения Pack.

4. **36/37/94 — GEO-классы импортируются только пока доступны удаляемые PC-классы.** При исполнении тела GeoSurfacePlanningView Python читает ReadySurfacePlanningView.model_config (`backend/app/application/worldData/planning/contracts/surfacePlanningView.py:80–83`). GeoSurfacePlanBundle читает SurfacePlanBundle.model_config (`backend/app/application/worldData/planning/contracts/surfacePlanBundle.py:61–64`). Удаление PC-объявлений ломает импорт раньше вызова валидатора coherent. Закрепить конфигурацию за сохраняемым владельцем перед удалением. В чистом процессе импортировать обе GEO-модели без PC-классов и проверить сохранение strict/frozen/extra/revalidation настроек.

Решение о версии Pack provenance остаётся у владельца Spatial, как зафиксировано в [основном плане](geo-1-designed-water.md#i93-реестр-удаления-старого-пути-гидрологии).
