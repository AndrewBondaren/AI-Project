# Pack settlement — framed payload и историческое чтение

Статическая сверка 2026-11-12. Срез роли settlement из [инвентаря Pack](pack-v2-domain-contract-spec.md#6-роли-payload-сверка-writer--reader--retention-2026-11-12). Только документация: runtime/SQL/shared validators не менялись, тесты не запускались. Write-операции другого агента этим срезом не перепроектируются.

## Существующая цепочка и формат

`WorldPackWriter.encode_settlement_structure_tmp` → `packBlobWire.write_settlement_structure_blob` → tmp bytes; `publish_settlement_structure` переносит готовый blob и обновляет manifest metadata. Новый write-path получает подготовленный ref, а не tmp path или инструкцию дописать district. Подготовка/append готового результата остаются у владельца producer; Pack final prepare не исполняет их заново.

Existing encoder нового blob использует `(codec_version, PAYLOAD_KIND_SETTLEMENT_STRUCTURE)` + magic SSF1 + последовательность records. Каждый record — uint32 network-order длина compressed bytes и отдельный Zstd JSON frame. Первый record содержит settlement_uid/barrier_cells, последующие — DistrictStructureWire. Existing append сохраняет bytes prefix и добавляет районы в конце. Если existing blob framed, его прежний header не заменяется incoming header. Эти правила не подменять generic merge по UID.

Existing parser после проверки version/kind принимает framed либо прежний single-Zstd JSON. `tests/test_c24_district_packing.py` содержит проверки append без recompress prefix и чтения прежнего представления; `tests/test_transition_pack_wire.py` проверяет обе формы с custom transition registry. Это найденные тесты, а не результат нового запуска. Поддержка прежнего представления в текущем parser не разрешает автоматически включать legacy fallback в целевой единственный decoder. Целевой registered descriptor должен явно закрепить одно согласованное представление; framed соответствует текущему encoder, а перенос поддерживаемых прежних bytes остаётся отдельным migration gate.

## Общие POJO и порядок наложения

Typed read T — existing SettlementStructureWire с DistrictStructureWire, AreaStructureWire/AreaSlotWire, BuildingShellWire, ShellCellWire и BuildingInteriorTransitionsWire. Их зеркальные PackSettlementPayload/Transition POJO не вводятся. ShellCellWire хранит world x/y/z, не chunk-local lx/ly; payload.settlement_uid связывается с settlement address.location_uid. TerritoryVolume находится в metadata, не в blob.

`settlementStructureIndex.index_shell_cells` использует last-write-wins: root barriers → каждый district и его barriers → каждая area (yard, barriers, small_layouts, buildings/shell_cells). Порядок districts, areas и вложенных cells имеет смысл при совпадении координат. Codec сохраняет этот порядок; сортировка/дедупликация по UID или координатам при decode не допускается как «канонизация». Manifest packed_district_uids описывает учтённый набор отдельно; механически заменять payload sequence этим набором нельзя. Растеризация/построение coordinate index — производная операция чтения, не сохранённый второй источник истины и не обязанность decoder.

## Подтверждённая зависимость от Transition registry

`parse_settlement_structure_payload/_parse_frames` передают transition_type_registry в model_validate. `Transition._type_contract` разрешает system_transition_type через registry и выбирает/проверяет type_params и направления; `BuildingInteriorTransitionsWire._scope` дополнительно проверяет registry entry, directional/runtime запреты и building level scope. Без context оба пути используют canonical_engine registry. Следовательно, существующий decoder может отклонить исторический custom key без registry либо оценить его по изменённой текущей декларации.

Это реальная зависимость owning validation, а не повод Pack запрашивать latest Source/Transitions при read_part. Нельзя молча убрать проверки, заменять custom key встроенным типом или встраивать самодельный registry snapshot в Pack payload. Требование к владельцу Transitions при его миграции: предъявить способ строгого восстановления сохранённого Transition с сохранением type_params/semantics без live registry lookup и без зеркального POJO. Если контракт потребует pinned dependency, её concrete descriptor/closure и mapping согласуются отдельно; текущий Pack срез их не придумывает. Эта зависимость блокирует полный typed settlement read с custom transitions, но не остальные payload bindings.

Отсутствующий `BuildingShellWire.interior_transitions` означает legacy shell-only данные, а не пустой список переходов. Existing `building_with_interior_transitions` в таком случае выдаёт InteriorTransitionsRebuildRequired; отсутствие building — KeyError. Не превращать первый случай в успешный пустой transitions result и не объявлять весь settlement отсутствующим. Специализированный query не запускает rebuild. Маркер building-interior-transitions-v1 является реальным persisted discriminator: он входит в обязательный финальный аудит версионных обозначений, но не меняется слепой заменой и не даёт разрешения удалить historical semantics.

## Уточнение границы по фактическим callers (2026-11-13)

`WorldPackReader.read_settlement_structure(..., registry=None)` передаёт registry в parser. Просмотренные `PackRenderReadFacade` и `SettlementStructureRaster` вызывают этот метод без registry, то есть существующий путь пользуется canonical_engine fallback. Это не доказательство корректного исторического custom-registry чтения. Сам факт наличия параметра registry в parser не означает, что нужная версия уже передаётся production caller.

Зависимость сильнее проверки наличия ключа: `Transition._type_contract` выбирает класс type_params, может материализовать StaircaseTransitionParams и defaults discovery/direction; `BuildingInteriorTransitionsWire._scope` проверяет directional/runtime запреты по registry entry. Поэтому нельзя решить вопрос пропуском membership check или подстановкой пустого registry: это способно изменить смысл восстановленного Transition. Pack не должен самостоятельно переписывать эти правила владельца.

**Направление для согласования:** сохранить существующую семантику Transition и передавать явно подготовленный исторический контекст; не создавать registry и не искать latest внутри decoder. Выбор representation исторического контекста и строгого восстановления остаётся у владельца Transition. До предъявления его контракта общий Pack decode port не расширяется произвольным context: dict/Any, callback или registry resolver. Существующий shell-only путь и независимые Pack bindings продолжаются; полнота typed settlement с custom transitions не объявляется закрытой. Это направление не выбирает новый snapshot store и не решает отложенный PACK-METADATA-PLANNING.

Подготовленный текст уточнения владельцу (не отправлен):

> Для Pack settlement требуется сохранить текущую семантику Transition при историческом чтении. Сейчас parser принимает WorldTransitionTypeRegistry через validation context, а без него использует canonical_engine; `_type_contract` не только проверяет key, но и выбирает type_params/defaults. Предъявите owning контракт восстановления сохранённого Transition: конкретный тип необходимого исторического контекста, способ его привязки к сохранённой версии, допустимые defaults и typed отказ при отсутствии контекста. Pack не выполняет latest lookup, генерацию или публичный вызов вашего pipeline. Если необходима persisted dependency, укажите её существующий descriptor и retention obligations; новый storage/зеркальный Transition не вводить без обоснования. Нужен пример custom key, смысл которого изменился в latest registry, с неизменным результатом чтения старой версии.

## Status, packed districts и конечный payload

Trace [settlement_structure_status_for](../../backend/app/dataModel/worldPack/wire/settlementStructureStatus.py) и [SettlementOutdoorPackingJob](../../backend/app/application/worldData/settlementOutdoor/settlementOutdoorPackingJob.py): после encode tmp и SQL persist producer добавляет текущий district UID в packed, вычисляет status по census и передаёт packed/status в publish. Helper использует `set(packed) == set(census)`, не counts. Пустой packed даёт absent; complete требует непустого census и has_file=True; иначе partial.

In-memory вызов existing pure policy через backend/.venv Python `-B` подтвердил: empty/empty → absent; [A]/[A] с has_file=True → complete, с False → partial; [A]/[B], [A]/[A,B], [A,B]/[A] и [A]/empty → partial. Это проверка policy, не integrated acceptance.

[WorldPackWriter.publish_settlement_structure](../../backend/app/application/worldData/pack/io/worldPackWriter.py) не вычисляет status заново. `packed_district_uids=None` сохраняет прежний список, `structure_status=None` независимо сохраняет прежний status; без предыдущей row это [] и absent. Явный [] очищает packed и сам по себе не изменяет status. Эти локальные эффекты уже приняты [write-планом](pack-v2-public-write-operations.md); final validator не заменяет их скрытым пересчётом. Новая функция статуса внутри Pack не нужна.

Target final admission использует материализованные owning SettlementStructureWire, PackSettlementAssembly и предъявленный PackSettlementCoverage. PackPreparationOperation обеспечивает bounded verified read и holds; pure PackPreparationValidator проверяет settlement UID относительно адреса, уникальность metadata/census UID и связь с coverage. Каждый заявленный packed UID должен присутствовать в конечном payload. Для результата C24, удостоверяющего полный упакованный набор, множество payload districts сопоставляется с этим набором целиком, а не только текущим district или числом frames. Основание — [ТЗ settlement, C14/C24](../../docs/tz_settlement_outdoor.md): packed описывает районы, уже находящиеся в BLOB. Отсутствующее полное evidence не заменяется live C23 SQL read из Pack.

Временное множество district UID для сравнения не разрешает менять порядок или дедуплицировать payload. Existing append сохраняет кадры, last-write-wins reader зависит от порядка. Новый глобальный запрет повторяющегося district frame не выводится из уникальности packed/census metadata; ограничения payload проверяются owning схемой.

Legacy producer передаёт has_file=True до publish — это его аргумент orchestration, не доказательство доступности target artifact. Перед READY нужны точный sealed/held verified payload и соответствующие census/provenance. Для inherited/None-полей сохраняется основание из базы; замена BLOB не разрешает несовместимую metadata только потому, что локальный write принял None.

Критерии: равные counts разных UID не дают complete; packed UID отсутствует в payload — отказ; BLOB отличается от удостоверенного coverage — отказ; None и [] различаются; absent metadata не удаляет header-only BLOB автоматически; final validator не сортирует districts и не запускает layout/SQL/producer. Ошибки передаются общим final-prepare контрактом, без нового SettlementError DTO. Runtime не менялся; порядок legacy encode → SQL → publish не переставлялся.

## Bounded admission и storage closure

### Конкретизация SettlementStructureDecoder

Проектный pure класс `SettlementStructureDecoder` в `backend/app/application/worldData/pack/encoding/settlementStructureFormat.py` получает fixed codec version и DecodeLimits. Результат — единственный owning SettlementStructureWire. Для нового descriptor из [binding roster](pack-payload-binding-roster.md) применяется framed представление SSF1; старый single-Zstd parser не подключается как неявный fallback. Producer append и сохранение старого header/prefix не исполняются decoder или final prepare заново.

**Порядок проверки framing:** encoded cap до decode → минимальный TileCodec header и точные version/kind → SSF1 → последовательный обход records. До каждого чтения проверяется наличие полного uint32 length prefix, затем попадание объявленного compressed span в оставшиеся bytes. Огромная длина не используется для allocation до этой проверки. Frame распаковывается в пределах остатка общего decompressed budget; JSON record должен быть object и пройти структурные limits до чрезмерной материализации. После последнего record не допускается необработанный хвост. Нулевое число records — missing header; один header без districts допустим. Отдельный пустой/повреждённый compressed frame не трактуется как отсутствующий район.

Первый record описывает settlement_uid и barrier_cells. settlement_uid — обязательная owning string, без str(...) coercion; barrier_cells при отсутствии использует existing default SettlementStructureWire, а не новый literal decoder. Остальные records — DistrictStructureWire в исходном порядке. Header не является вторым полным SettlementStructureWire с независимым districts; для временного разбора не создаётся зеркальная публичная модель. Неизвестные/duplicate JSON keys не теряются при извлечении известных полей. Decoded header и districts собираются в единственный owning payload после admission.

| Вложенные данные | Что сохраняется / проверяется |
|---|---|
| Root, districts, areas, buildings | Исходный порядок; mandatory fields/defaults — по owning моделям. Наличие списка не даёт права сортировать по UID |
| ShellCellWire x/y/z | Exact integer world coordinates, не chunk-local. Совпадения координат не удаляются при decode: индекс позднее применяет прежний last-write-wins |
| ShellCellWire.system_facing | Существующее поле str или None; нельзя механически заменить правилом enum Facing от AreaSlotWire |
| AreaSlotWire.facing | Canonical owning Facing wire value, без permissive aliases/coercion. Остальные числовые поля/defaults сохраняют owning смысл |
| small_layouts и вложенные cells | Порядок обоих уровней сохраняется; целевой immutable output использует tuple на обоих уровнях |
| interior_transitions=None | Сохраняется как отсутствие блока, а не превращается в пустой transitions tuple. Специализированный query сохраняет InteriorTransitionsRebuildRequired; decoder не запускает rebuild |
| Непустой interior transitions block | Existing discriminator, unique levels/transitions, world/endpoint scope и type_params проверяются owning контрактом с соответствующим историческим registry |

Полное owning дерево постепенно адаптируется к strict/frozen/revalidate и tuple без зеркальных PackSettlementPayload/PackTransition моделей. Одна frozen outer model с mutable lists не считается готовым T. `validate` проверяет фактические значения forged instances, не доверяет наличию класса. Числовые/default-поля берутся из owning declarations; не добавлять глобальный запрет повторных district/building UID без доказанного правила: существующий building query выбирает первое вхождение, а raster index накладывает клетки последовательно.

**Точный порядок наложения, который codec обязан сохранить:** root barriers → для каждого district его barriers → для каждой area yard cells → area barriers → small_layouts → buildings.shell_cells. Последняя клетка координаты выигрывает в index_shell_cells. Эта derived индексация остаётся за reader/consumer; decoder возвращает исходное дерево, не готовый dict координат. Metadata packed_district_uids и payload sequence не заменяют друг друга.

### Граница контекстного декодирования transitions

У общего `PackPartPayloadDecoder.decode(payload, format_version)` пока нет аргумента historical registry. Поэтому нельзя объявить новый SettlementStructureDecoder полностью подключённым к этому port одним переименованием existing parser. Нельзя также хранить mutable current registry в singleton decoder: WorldTransitionTypeRegistry сейчас RootModel[list[...]], а не неизменяемая закреплённая версия.

Для собственной pure проверки settlement требуется явно подготовленный контекст owning registry при наличии transition block; способ его получения/идентификации относится к интеграционному binding. Pure codec не делает lookup/capture и не подменяет отсутствие нужного контекста canonical_engine(). Read/final prepare должны получать один и тот же исторический смысл, а не независимо текущие defaults. Контекстный adapter к общему port конкретизируется отдельно; этот пробел не является поводом менять Planning, блокировать остальные Pack bindings или пропускать validation переходов. Ошибка получения контекста не доказывает повреждение bytes и не должна автоматически становиться INVALID_PAYLOAD.

Локальные malformed envelope/frame/JSON/field отказы сопоставляются с INVALID_PAYLOAD, превышение суммарного byte/structure budget — BUDGET_EXCEEDED, неподдержанный descriptor/version — CONTRACT_MISMATCH. Pure codec не создаёт refusal с pin/publication; его оформляет Pack operation. Wrong settlement_uid относительно address проверяется в contextual admission после decode, не исправляется присваиванием UID caller.

Проверки реализации: header-only payload; truncated prefix/frame; большой declared length; несколько допустимых frames, суммарно превышающих budget; неизвестный header key; одинаковые координаты в разных слоях с прежним конечным результатом; порядок districts после append; shell-only против explicit empty transitions; historical custom type без latest lookup; другой world/address; forged mutable вложение. Проверки описаны, не запускались. Runtime и модели других доменов не изменены.

Storage остаётся BLOB bytes binding. Предлагаемый Pack-owned модуль `encoding/settlementStructureFormat.py` переиспользует owning POJO и согласованную framing схему. Codec — pure, без filesystem/SQL/registry resolver/public calls. Проверяет byte budget до parse, version/kind, обязательный header, каждую record length и границы. Ограничение decompressed output действует как на frame, так и на их суммарный decoded объём: множество маленьких compressed frames не обходят общий лимит. Existing _parse_frames хранит все records и не задаёт такой лимит, поэтому готовым bounded decoder не является.

Текущий framed parser также берёт только известные header поля, использует str(header[settlement_uid]) и default [] для barriers; это не strict admission. Owning nested модели содержат lists/extra=ignore и normalization validators, Transition тоже имеет вложенные lists. Их immutable/strict адаптация требует согласованной миграции общей модели, без попутной правки интегрированных методов других доменов. Field/logic error mapping и конкретные format/read IDs/budgets ещё требуют реализации и приёмки.

В просмотренном дереве settlement/Transition нет ArtifactRef: endpoints, location/level/node UID, glossary_ref/tag_refs — доменные ссылки, не storage refs. У текущего payload нет дочернего artifact closure. Это не доказательство достаточности будущего исторического registry contract; если он добавит pinned dependency, closure roster должен быть обновлён явно. Source provenance учитывается отдельно.

Проверки: truncated record length/body; неверный header/kind; missing header; cumulative decompression overflow; сохранение district/cell порядка и last-write-wins; settlement UID/address mismatch; shell-only отличается от empty interior block; custom transition round-trip после изменения latest registry по принятому owning контракту; immutable result после guard close; отсутствие IO/producer calls из decoder. Полный binding остаётся OPEN по явно перечисленным пробелам, а не по ожиданию миграции всех доменов.
