## 1. Основания, приоритет и изменение failure model

Источники: `artifacts-stage-recovery-contract.md`, `artifacts-stage-recovery-owning-resolution.md` (RC-CONSTRUCTION, P1.1, Q1, Q5), `artifacts-stage-recovery-publication-resolution.md` (Q5/Q6), `dag-stage-recovery-transition-resolution.md`, правила `interdomain-contract-coordination.mdc` и `dag-generator-interface.mdc`. Это предложение заменяет research OPEN физического механизма и caller wiring конкретным решением ниже; прежние документы не становятся автоматически принятыми. Этап 1 и его порядок не меняются. Здесь проектируется целиком этап 2.

Existing: ContentAddressedBlobBackend выполняет IO в thread executor caller-процесса; SqliteArtifactCatalog.reserve/seal, SqliteArtifactLeases.writer/cancel, existing Snapshot UOW/ACK/quarantine; Engine сохраняет CALL/checkpoint. Proposed: все Stage* rows и stage recovery API из прежних планов, плюс дельта этого документа. Нельзя выдавать proposed таблицы за существующую реализацию.

Дельта: один узкий Windows service `ArtifactPhysicalHost` на один установленный storage root. Он исполняет только физические команды Artifacts; не запускает DAG, stage, recover, operation cancellation, не выбирает следующий lifecycle переход. Он не второй lifecycle coordinator. В нём живут backend, root gate и принятые IO tasks. SQL authority и решения lifecycle остаются в SqliteStageAttemptStore / jobs, Publication сохраняет operation authority. Новый универсальный журнал не нужен.

Область доказательства: один хост, стабильный локальный NTFS root, same-volume no-overwrite placement, локальная SQLite, исправные ОС/FS/накопитель, cooperating mutators. Нет network FS, external IO agents, mmap writers, передачи файловых handles дочерним процессам, VM rollback/clone, восстановления DB отдельно от root. Повреждение носителя — infrastructure/integrity failure, не разрешение retry. Перезагрузка не считается доказательством успешности или durability старого write; после неё обязательны SQL reconciliation и hash/size verification.

## 2. Конкретный physical owner и доказательство

Новые внутренние классы в `app/storage/artifacts/physicalHost/`:

| Класс / метод | Роль, зависимости, эффекты | Приёмка / признак отказа |
|---|---|---|
| WindowsBootLatch.enter(root_identity) -> BootSession | Win32 RegCreateKeyExW; атомарно создаёт заранее закреплённый HKLM volatile key для installation/root. Только REG_CREATED_NEW_KEY допускает host; REG_OPENED_EXISTING_KEY даёт PhysicalHostRestartRequired. Не SQL authority | Два запуска в одной загрузке: допускается ровно один; удаление ключа, смена namespace для обхода — отказ |
| ArtifactPhysicalHost.start(config); submit(command); fence_and_drain(execution); finish(session) | Windows service; owns backend/executor, strong references ко всем принятым tasks и handles. Имеет собственный existing Snapshot access graph к той же DB. Не вызывает публичные операции иных доменов | Caller kill не уничтожает IO owner; host не выдаёт permit и не пишет operation terminal |
| PhysicalExecutionSession | Непередаваемый runtime resource host: exact binding/generation/claim, command serialization, accepted futures, closing flag, gate ownership. Методы submit, close_dispatch, join | Нельзя dispatch после closing; один владелец каждого future; отсутствие session не считается proof для произвольной legacy execution |
| ArtifactPhysicalClient | Аутентифицированный local named-pipe adapter; переносит immutable command/result, не OS handles. Disconnect лишь теряет ответ, не отменяет принятую работу | Повтор запроса не запускает второй write; нет local backend fallback |
| WindowsBlobEffectGate / BlobEffectGuard | Existing proposed root LockFileEx exclusion, внутри host; acquisition и close принадлежат session | No SQL→gate wait; close только после join; lock не называется process-loss evidence |
| ContentAddressedBlobBackend | Единственный исполнитель mkdir/temp/write/flush/fsync/place/verify/unlink. Все authorized методы вызываются только host | Любой authorized filesystem syscall в DAG/caller или unguarded finally — отказ |

Composition: service bootstrap создаёт latch → existing Snapshot registry/access graph → SqliteStageAttemptStore → gate → backend/format registry → ArtifactPhysicalHost. Caller graph создаёт client → ArtifactStageWriter/Finalizer/Recovery → StageAttemptService. Нет late setters, циклов и optional bypass. Backend не приобретает local claim. Host получает только internal scoped authority adapter Artifacts, не Publication service.

Boot latch: фиксированный ключ `HKLM\SOFTWARE\AIProject\ArtifactPhysicalHosts\<installation-id>`; installation-id неизменно закреплён за canonical volume/root при установке, не генерируется при restart. Parent key nonvolatile, leaf создаётся REG_OPTION_VOLATILE. ACL допускает создание только сервисной identity, не callers; приложение никогда не удаляет leaf, в том числе при clean shutdown. Existing key означает отказ старта даже после штатного stop. Не использовать HKCU, hive unload, uptime, PID, timestamps, новый случайный namespace. Ошибка registry/ACL/config — fail before IO. SC_ACTION_REBOOT допустим как deployment action, но запрос reboot не является evidence; этот план не выполняет reboot и не меняет настройки компьютера.

Microsoft документирует сохранение HKLM volatile key до полного shutdown; Fast Startup не равен этому барьеру. Источники: [RegCreateKeyEx](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-regcreatekeyexa), [full restart](https://learn.microsoft.com/en-us/troubleshoot/windows-client/setup-upgrade-and-drivers/fast-startup-causes-system-hibernation-shutdown-fail). Из этих гарантий и ограничения локального исправного storage следует выбранный протокол: потерянный host невозможно заменить в том же kernel lifetime; новый host допускается только после полного boot cycle. Hibernation сохраняет latch и не разрешает замену.

**Доказательство:**
1. До любого accepted IO host успешно входит в latch. В одной загрузке существует не более одного допустимого host. Все authorized writer/finalizer effects исполняются его threads.
2. При живом host fence_and_drain закрывает dispatch exact execution, под gate фиксирует prohibition через existing UOW, ждёт все ранее accepted tasks до реального completion. Уже ожидающий command проходит fresh authority check после gate, поэтому после prohibition отклоняется до syscall. In-flight batch должен завершиться до fence ACK.
3. Потеря caller не теряет host futures. Потеря host блокирует его замену до full boot; ни lock acquisition, ни timeout, ни запись prohibition не разблокируют startup.
4. После полного boot старых threads/kernel requests этого host нет; старый caller, если он восстановлен, имеет только RPC и старый permit, которые проходят новые SQL checks. До release successor не выдаётся; после prohibition/release stale write и cleanup отвергаются.
5. Повторно упавший finalizer — тот же случай: его cleanup выполнялся host, а не caller. Потеря host повторно требует полного boot. Отдельного теряемого witness владельца не возникает.

Невозможность завершить IO/перезапустить хост — operational failure, не успешный recovery. Exact ошибка PhysicalHostRestartRequired сохраняет claims/holds и требует полного restart, затем того же recovery CALL. Бесконечное ожидание не называется готовностью. Это конкретная политика восстановления, а не Unresolved вместо механизма.

## 3. Владение на каждом await

| Ожидание | Владелец работы и ресурса | Cancellation / lost ACK |
|---|---|---|
| acquisition commit | ArtifactStageWriter durable exact claim_id; shielded acquisition task | До confirmed acquisition ни host registration, ни IO. При unknown authoritative exact reread; новый claim_id запрещён |
| register session / gate | Host после принятия команды; caller до принятия владеет только запросом | Session strong-owned до completion/reconciliation. Named-pipe disconnect не освобождает session. Gate waiter отменяется только host с join acquisition и закрытием действительно полученного guard |
| IO / verify | Host session и её worker future | Caller cancellation лишь запрещает последующий dispatch; принятый syscall ждут до completion. CancelIo не считается completion |
| join | Та же session; один cleanup task | Повторная cancellation фиксируется, но не отменяет cleanup task и не создаёт новый. Shield-loop до terminal task result |
| cleanup | Host, exact temp `.tmp-stage-<claim_id>.part`; gate held | Только exact own temp; final path никогда не удаляется finalizer. Missing temp — идемпотентный cleanup после drain, не evidence drain |
| release commit | ArtifactStageFinalizer/Writer владеет shielded task; host session остаётся closing и удерживает guard до confirmed result | Unknown сохраняет session/guard при живом caller; при disconnect host закрывает guard лишь после своих IO, но SQL release не предполагает. Durable pending восстанавливается exact reread |
| exit | Runtime contexts инвалидируют handles | __aexit__ не пишет release, не запускает IO, не имитирует success при unknown |

Host не держит gate бессрочно ради потерянного RPC ACK: после join допускается его закрытие без SQL release, если session остаётся closing и prohibition подтверждён. Повторный finalizer reacquires gate и перепроверяет SQL. Если prohibition commit unknown — session запрещает dispatch локально, SQL reconciliation обязательна до обработки дальнейших команд этой execution. Host shutdown закрывает admission команд и joins все tasks; принудительное завершение переводит систему в boot-required режим.

## 4. Persistence: транзакции и ограничения

Все перечисленные write transitions: existing Snapshot UOW, BEGIN IMMEDIATE, exact shared registry/access/coordinator, confirmed commit до результата. No nested transaction, no SQL lock во время gate/IO/join. UnknownCommitOutcome не rollback; connection quarantine и authoritative reread existing infrastructure.

Reuse proposed StageBindingRow, GenerationRow, AcquisitionRow, CompletionRow, ReleaseRow, EffectProhibitionRow, LocalClaimLinkRow из owning resolution. Дополнить acquisition обязательным `physical_protocol=HOST_BOOT_V1` для этого маршрута. Legacy rows не получают это значение миграцией по умолчанию. Новые данные insert-only; FK composite `(operation_id,stage_id,generation,claim_id)`; acquisition unique generation и claim_id; completion unique logical stage; local link unique local event; release unique exact acquisition. Generation CHECK positive; initial g=1/predecessor NULL; successor g=predecessor+1; UNIQUE(operation_id,stage_id,predecessor_generation) для non-NULL predecessor и FK predecessor к generation. UPDATE/DELETE этих facts не предоставляются; repository и integrity decoder отвергают нарушения.

| Переход / concrete method SqliteStageAttemptStore | Вход → факт / результат | Crash до/после commit |
|---|---|---|
| begin(binding) | Exact immutable binding, writable operation → binding+g1 атомарно. Replay возвращает ту же g1, никогда latest generation | До: нет права effects. После lost ACK: exact reread, тот же permit; consumed permit не допускает второго writer |
| acquire(permit,claim_id) | Current allowed generation, no completion/prohibition/release, open/current operation → acquisition с protocol | После commit/no session: full claim active, no-link recovery допустим через host barrier; отсутствие local link не освобождает автоматически |
| reserve_stage(full) → catalog.reserve_in_scope(scope,binding.lease,binding.artifact) | В ОДНОМ UOW: exact acquisition, issued WRITE handle, current authority, отсутствие prohibition/release → existing catalog/hold predicates и reservation | P/X первым запрещает reserve без mutations; reserve первым сохраняет hold, который остаётся operation-owned до Publication final transaction. Legacy independently committing reserve здесь запрещён |
| local_writer(full,reservation) | Exact full claim, current writable authority → existing local acquisition + StageLocalClaimLink в одном UOW | Нет half-link. Replay сверяет exact row; не создаёт второй local claim |
| seal_stage(full,local,reservation) | Fresh no prohibition/release; live session; linked local+hold; verified ref → scoped catalog seal + StageCompletionRow атомарно | До: completion нет даже при наличии final file. После: historical completion есть даже при потере ответа |
| prohibit(execution) | Exact acquired generation → insert prohibition, completion сохраняется | До: host продолжает удерживать gate/closing. После: WRITE/VERIFY/seal запрещены, cleanup разрешён по finalization mode |
| release_finalized(execution) | Host drain + exact cleanup завершены, gate held; fresh prohibition, exact link → existing scoped local release (если link есть) + full release одним UOW | После lost ACK: reread обоих facts; одна половина — invariant fault. No-link: только full release, если protocol и полная integrity доказаны |
| successor(binding, predecessor) | Нет completion; exact predecessor released+prohibited; fresh writable operation; generation CAS → g+1 | UNIQUE predecessor делает replay идемпотентным. Повтор recover(g) возвращает уже созданный g+1, не g+2; его consumption не запускается повторно |

Normal finish_live также закрывает dispatch и записывает prohibition перед общим release, даже после успешного seal; это унифицирует proof и не отменяет completion. Prohibition первым блокирует seal, seal первым сохраняет completion. Единственный normal release — finish_live после host join/cleanup. Recover сперва доводит exact execution до release, затем в коротком UOW: completion → Confirmed; closed/stale authority → Refused; иначе unique successor → Allowed. Confirmed не обещает current hold и не разрешает stage.

Unconsumed generation: recover exact generation при open authority возвращает тот же permit, не новую generation; при closed authority Refused. Acquisition без local link: host barrier + prohibition + deterministic cleanup, затем full release. Link без local acquisition/foreign event/legacy protocol — invariant/unsupported-protocol error, не wildcard release. Потеря ACK reserve не обходится новым ref: exact catalog/hold reread.

## 6. Publication, cancellation и гонки

Порядок Q5/Q6 сохраняется: закрытие admission → explicit Artifacts inventory/finalization → окончательная Publication transaction. Existing blocking cancel не меняет result union на Busy/Pending; close observation остаётся отдельным контрактом подготовленной цепочки. Сохранить отдельный blocker legacy local-only writer; данный host не получает право освобождать его claims.

SqliteArtifactLeases.cancel final UOW: current fence/operation/terminal и closed admission → все historical full acquisitions имеют exact releases → `_catalog._writers` пуст → integrity hold chains → release всех operation holds + SqliteOperationStore.record_terminal(OperationCancelled) → один confirmed commit. SqliteStageExecutionDrain.assert_drained — SQL-only predicate, без host/IO/cleanup; required dependency всех release/READY/fence paths. OperationLedger — validation/delegation. Snapshot driver — transaction/ACK/quarantine, не owner physical evidence.

Cancel close и successor сериализуются: close первым запрещает successor; successor первым может выдать permit, но закрытие admission до consumption запрещает acquire. Acquisition первым создаёт blocker и требует drain. Completion без release не снимает blocker. Два recover одного predecessor получают один successor. Два finalizer сериализуются host session/gate, release идемпотентен. Повторная cancellation не создаёт новую cleanup task; errors cleanup/release сохраняются с исходной cancellation как context. Unknown final cancel требует authoritative terminal+holds reread; никакого компенсирующего release.

## 7. Сценарии и проверяемые разрешающие факты

| Сценарий | Следующий переход разрешает только |
|---|---|
| Штатно | acquisition → local link → host write/verify → atomic seal/completion → close dispatch/prohibition/join/cleanup → atomic release → result |
| Crash до seal, включая после placement | Живой host drain либо full-boot startup barrier; prohibition; exact cleanup; release; fresh admission → successor. Final file сам completion не создаёт |
| Crash после seal | Exact completion + finalization release → Confirmed, без повторной записи |
| Lost begin/acquire ACK | Exact rows; повторное consumption запрещено; при acquired неизвестном исходе recovery |
| Lost seal ACK | Authoritative completion read; нет completion — finalization и successor, есть — finalization и Confirmed |
| Lost release ACK | Exact local/full release read. При отсутствии — повтор drain/cleanup/release; при unknown — никакого successor |
| Caller погиб во время cleanup | Host хранит future; другой finalizer joins ту же session. Если host тоже погиб — full restart |
| Host погиб до/после любой команды | Latch запрещает same-boot replacement. После полного restart SQL facts определяют cleanup/release, не память прежнего caller |
| Concurrent cancel/recover | Final successor UOW fresh authority; final cancel UOW complete drain predicate |
| Повторная cancellation на gate/IO/join/release | Один сильный owner task до completion; cancellation ACK не равен release |

## 8. Реализация после приёмки и acceptance matrix

Последовательность: contracts/POJO/composition → SQL constraints и scoped transitions → boot latch/host/session/transport → authorized backend и writer/finalizer → Engine CallOrigin/checkpoint/REPORT_UNKNOWN → DAG transport и Publication guards → fault suite. Каждый слой проверяется до следующего. Никакой production workflow/activation автоматически не добавляется.

Проверки обязательны: две DB connections на всех competing transitions; fault до/после каждого commit и ACK; kill caller при каждом await; kill host во время write/fsync/place/unlink и попытка same-boot replacement; full reboot test на изолированном стенде; повторный kill host в cleanup; paused stale caller после successor; повторная cancellation; no-link claim; legacy blocker; corrupt FK/link; replay recover(g) после consumption g+1; stage policy restore mismatch; checkpoint до begin; exact prepared identity; отсутствие local direct IO. Тест должен проверять отсутствие поздних old effects после Allowed, а не только final hash. Reboot тесты не выполняются на рабочей машине пользователя.

По правилам DAG: ветвление только parent; leaf напрямую вызывает один public domain operation; ни host, ни store, ни backend не выбирают DAG route; direct междоменных public calls нет. Вложенные physical алгоритмы — реализация атомарного Artifacts вызова. CRUD: новые facts создаются и читаются owning store; update/delete и новые настройки CRUD этим контрактом не предоставляются. Foreign operation/hold чтения и записи проходят существующие scoped Snapshot adapters; public зеркала и новые доменные функции отсутствуют. Критерий нарушения: любой обход shared UOW/drain или экспонирование storage/runtime handles в DAG.

Итоговый пакет конкретен, но архитектурная приёмка НЕ объявлена: требуется проверка назначенным DAG-координатором и решение пользователя о предложенном scope, особенно о service host и обязательном full restart при его потере. Это не запрос разработчику выбрать механизм. Передача пакета через пользователя; сообщений другим чатам нет. Runtime guarantees требуют перечисленных тестов после отдельного code-go.

Дополнительные основания: `artifacts-stage-persistence-contract.md`, `artifacts-stage-finalization-unified-contract.md` (reserve_stage/reserve_in_scope, U6), identity-план §§5.2–5.6. Уточнение ответственности host: RPC dispatcher не решает lifecycle. ## 10. Caller ↔ host: закрытый internal RPC v1

Модуль `app/storage/artifacts/physicalHost/protocol.py`, Artifacts internal wire, НЕ DAG/public POJO. Все records strict/frozen/extra-forbid. Existing StageBinding и ArtifactRef импортируются, не зеркалируются.

`ExecutionKey(binding: StageBinding, generation: positive int, claim_id: EntityUid)` — точный адрес acquisition, не право записи. `CommandKey(execution: ExecutionKey, verb: Literal[WRITE,SEAL,FINALIZE])`. Один key на verb на lifetime execution, без случайного request ID на reconnect. `HostHello(protocol_version=1, installation_id: EntityUid)` → `HostConnected(host_instance_id: UUID, protocol_version=1, installation_id)`; UUID коррелирует соединения, НЕ physical evidence. Server identity проверяется named-pipe ACL и service identity; remote pipes запрещены. Client с иным root/installation/version получает infrastructure contract failure до команд. SQL binding и issued host view проверяются независимо от pipe authentication.

`Execute(key, body)`, `Observe(key)` и `ReconcileFinalize(key, expected_failed_round)` — transport messages. Последний допустим только для FINALIZE и определён ниже; Execute/Observe никогда не перезапускают failed task. Execute body — discriminated union:

| Body / job | Вход | Результат после завершения |
|---|---|---|
| WriteCommand / HostWriteJob.run | key.verb=WRITE; `encoded: bytes` — exact artifact bytes; key.execution | Written(key, ref: ArtifactRef). Только после reserve_stage, atomic local acquisition/link, write и verify; local/full claims остаются live |
| SealCommand / HostSealJob.run | key.verb=SEAL, без payload | Sealed(key, ref). Только после atomic seal/completion confirmed commit |
| FinalizeCommand / HostFinalizeJob.run | key.verb=FINALIZE, без payload | Finalized(key). Только после prohibition, drain/cleanup и atomic local/full release confirmed commit |

Observe возвращает `CommandObservation(key, round: nonnegative int, state)`; state = NotAccepted | Running | Completed(result: Written|Sealed|Finalized) | Failed(failure: FailureEnvelope из §13) | EvidenceLost. Первый accepted task имеет round=0; NotAccepted также сообщает 0. Round — номер reconciliation FINALIZE в текущем host instance, НЕ generation/claim/новый command key. WRITE/SEAL всегда round=0. Running не содержит процент/timeout promise. Wrong body/key, другой binding для той же PK, mismatch encoded против сохранённых bytes или binding descriptor → invariant failure без IO. По key WRITE сравниваются полные bytes; hash не заменяет equality запросов. Encoded admission проверяет полный размер/hash и format/version до reserve. Повторный failure не запускает write снова.

`HostCommandDispatcher.execute` под одним session mutex атомарно помещает неизменяемый body и сильную ссылку на task в map ДО enqueue/первого await effects. Затем возвращает/ожидает observation того же task. Accepted и Running могут совпадать; отдельного durable accepted ACK нет. Частично полученный pipe frame не accepted. Разрыв соединения до принятия — NotAccepted, после — та же task. Дубликат одновременно с первым запросом присоединяется к task, не создаёт другую. Ни memory pressure, ни TTL не удаляют session до confirmed release; при нехватке памяти отказывают НОВЫМ executions до acceptance. После release допускается удаление body/futures: authoritative release запрещает WRITE/SEAL, FINALIZE возвращает Finalized. Это completion replay, не повтор эффектов.

**Reconnect:** client всегда выполняет Hello → Observe(exact original key), сохраняя исходные key/body в своём writer task. При Running ждёт тот же task через повтор Observe; сетевой polling не запускает jobs. При Completed/Failed доставляет результат. При NotAccepted в том же host instance допускается Execute того же command. Новый host instance после reboot: WRITE ранее acquired execution НЕ повторяется, даже если completion нет; возвращается EvidenceLost (не owning public Unresolved). Caller переводит это в failure category OUTCOME_UNKNOWN §13; DAG вызывает recover, который выполняет FINALIZE и только потом решает successor. SEAL в новом host: существующий exact completion возвращает Sealed, иначе EvidenceLost; seal по наличию файла запрещён. FINALIZE после reboot выполняется заново по exact acquisition и boot barrier. Отсутствующий acquisition — invariant error, не permission create.

Первый WRITE новой execution отличим без durable command journal: acquisition дополнена `host_instance_id` того host, которому выдана. `ArtifactStageWriter` сначала Hello, затем acquire(permit,claim_id,host_instance_id). Host допускает новый WRITE только если acquisition.host_instance_id == current host instance и нет P/X/C. Acquisition и host UUID не могут меняться. Acquisition старого host всегда идёт через FINALIZE. UUID не доказывает reboot; boot latch допускает сам host до выдачи Hello. Host, получивший acquisition своего UUID без session, знает, что он сам ещё не принимал команду: до release map не удаляется; crash требует нового instance и полного boot.

После caller crash новым stage CALL нельзя переподключиться для WRITE по старому permit: acquire отвергнет duplicate consumption. Только owning recovery получает exact ExecutionKey из store и посылает FINALIZE. Если старый caller всё ещё жив, FINALIZE под session mutex ставит closing до ожидания gate; новые WRITE/SEAL отвергаются. Уже принятый WRITE joins, затем P/cleanup/X. Старый caller, получивший Written поздно, не сможет Seal: closing и fresh P/X checks.

### Evidence и место commit

`HostWriteJob` восстанавливает внутренний `HostWriteView` только через `SqliteStageAttemptStore.open_host_write(key,current_host)` после exact row validation. View не public claim и не создаёт acquisition. Он содержит correlation к существующей full acquisition; `reserve_stage(view)` и `local_writer(view,reservation)` используют те же scoped predicates. Host session удерживает issued local handle. В caller не остаётся второй local context. Full caller context после acquisition — только correlation/wait, его exit не освобождает claims.

`HostSealJob` требует Written именно этой session, open dispatch, exact local handle и reservation; держит session mutex против FINALIZE. Вызывает `seal_stage(view,local,reservation)`; store в одном UOW повторяет authority/no P/X/hold predicates. Verified runtime fact никогда не приходит из client body. Completion записывается вместе с scoped catalog seal. Caller получает Sealed, но сам seal не коммитит.

`HostFinalizeJob` — concrete physical implementation ArtifactStageFinalizer: closing → дождаться terminal WRITE task (включая join и подтверждённый close его guard) → acquire собственного нового guard → confirmed prohibition → exact temp cleanup + join → `release_finalized(view,guard)` → close своего guard → Completed. WRITE и FINALIZE не передают друг другу guard и никогда не владеют им одновременно. При ожидании WRITE/gate не держать session mutex. Closing уже выставлен и запрещает новые submissions; completion callbacks имеют независимый путь. Store получает issued in-process `DrainedExecution` от job после join/cleanup, привязанный к key/guard/session; constructor private, одноразовый, не сериализуется. Это обязательный параметр release, дополнительно к fresh SQL predicates. После reboot view создаётся для FINALIZE из acquisition, boot admission и SQL, не как WRITE view. При no-link cleanup допускается только после P и coherent recheck отсутствия link; physical dispatch требует link, поэтому поздний reserve/local уже заблокированы.

`ArtifactStageWriter`: Hello → acquire → Execute WRITE → Execute SEAL → Execute FINALIZE → вернуть ref. `ArtifactStageFinalizer.finish_live` — client адаптер к тому же FINALIZE. `finalize_execution` и recover используют lookup ExecutionKey → FINALIZE; они не выдаются за write. Recovery получает Finalized как ACK, затем сам authoritative reread X/C в finish_recovery UOW, а не доверяет RPC bool. Это единственное проверяемое основание caller: exact committed facts, произведённые host-owned job. Нет удалённого proof-token для seal/release.

Если SQL commit внутри host unknown, task выдаёт Failed(UNKNOWN_COMMIT), не provisional success. Execute/Observe после Failed всегда возвращают сохранённый исход и никогда не делают SQL reread/IO. Для failed SEAL caller обращается к owning recover: FINALIZE и finish_recovery authoritative reread C, без перезапуска SEAL. Для failed FINALIZE повторная public owning finalization использует только ReconcileFinalize по протоколу §10.1. Повтор WRITE после Failed запрещён. Errors всех rounds сохраняются в map до X; их отсутствие после reboot обозначается EvidenceLost, не придуманным failure cause.

§3 release ownership уточняется: release commit task и guard принадлежат host FinalizeJob, caller ждёт только RPC. Caller cancellation/disconnect не отменяет job. Repeated cancellation caller shield-loop ждёт один client cleanup task; если host недоступен, durable acquisition остаётся blocker, наружу infrastructure/unknown, не ложное Cancelled success. Host failure посреди release требует boot/reconciliation. При confirmed X job может освободить ресурсы до доставки ACK. Все commands после X сверяют exact persisted identity и ничего не пишут.

### 10.1. Единственный переход Failed FINALIZE → reconciliation

`ReconcileFinalize(key, expected_failed_round: nonnegative int)` — явная просьба повторной owning finalization после наблюдения Failed; не действие Observe и не автоматический retry dispatcher. Client facade при НОВОМ вызове finalize_execution/recover делает Hello/Observe: NotAccepted → Execute FINALIZE; Running → await; Completed → exact X reread; Failed(r) → ровно один ReconcileFinalize(key,r). Если новый round тоже failed, facade возвращает ошибку, не зацикливается. Повторная cancellation не считается новым вызовом и не повышает round. Reconnect одного вызова сохраняет expected_failed_round и повторяет тот же ReconcileFinalize, а не подставляет вновь прочитанный номер.

`HostCommandDispatcher.reconcile_finalize` под session mutex выполняет единственный CAS:

1. Проверить verb FINALIZE, exact key/body/acquisition identity и current host instance. Чужой key — CONTRACT failure. SQL rechecks выполняет job после mutex, не dispatcher внутри mutex.
2. Если current round == expected_failed_round и state == Failed: task должна быть terminal с `resources_closed=True`, либо session помечена poisoned. При poisoned вернуть исходный failure с RESTART_HOST_THEN_RECOVER без нового task. Для завершённой ordinary failure сохранить исходный envelope в history, выставить closing (он никогда не сбрасывается), создать round+1 Running со strong task reference и immutable predecessor round. Это атомарная точка принятия reconciliation.
3. Если current round > expected_failed_round, вернуть observation current round: это replay уже принятого запроса, НЕ новый round. Если equal, но Running/Completed — вернуть текущий observation без запуска. Если expected_failed_round > current round или FINALIZE ещё не accepted — CONTRACT failure без effects.
4. Отпустить mutex. Новый HostFinalizeJob сперва восстановит lawful SQL connection и перечитает exact X/C/P/link. X есть → Finalized без physical work; X нет → новый gate acquisition, P, drain/cleanup/release по §10.2. Unknown/read failure → Failed текущего round. Closing и prohibition не откатываются ни при каком исходе.

Одновременные ReconcileFinalize(r) создают ровно один r+1. Поздний повтор r после failure r+1 возвращает r+1, но не запускает r+2. Только отдельный новый owning вызов, наблюдавший failure r+1, может запросить r+2. History нужна для correlation/diagnostics, не authority и не новый durable журнал; после host loss boot barrier и SQL факты заменяют runtime rounds. На новом host client начинает Observe/Execute FINALIZE с round=0, не переносит старый CAS. WRITE/SEAL остаются terminal в round=0 при любой reconciliation, их повторное исполнение невозможно.

### 10.2. Gate lifetime: guard принадлежит одному physical batch

Нормативное уточнение прежней таблицы ресурсов: session хранит strong references и состояние владения, но НЕ держит guard между commands. Guard — private resource job, не shared mutable session handle; handoff WRITE→FINALIZE отсутствует. `resources_closed` выставляет job только после join всех worker futures, закрытия data handles и подтверждённого Unlock/Close guard. Никакой terminal Written/Failed не публикуется раньше этого resource epilogue. SQL completion может быть durable раньше terminal RPC outcome — это не противоречие.

| Путь | Exact последовательность владения |
|---|---|
| Successful WRITE | reserve/local → acquire G_write → fresh authority → write/verify и собственный cleanup → join всех IO/close data handles → close G_write → resources_closed → Written. Full/local claims продолжают жить; guard уже отсутствует |
| Failed WRITE | Зафиксировать primary error, запретить дальнейший dispatch этой WRITE task → join всех принятых IO → попытка exact cleanup только при lawful authority под G_write (иначе оставить temp finalizer) → close G_write → Failed с обеими причинами. Ошибка cleanup не отменяет join/close. Failed не выдаётся пока worker ещё способен писать |
| FINALIZE concurrent WRITE | Под mutex закрыть admission новых WRITE/SEAL → отпустить mutex → ждать WRITE task resource epilogue. WRITE не ждёт FINALIZE и не пытается заново получить свой guard. Затем FINALIZE acquire G_finalize → fresh P/authority → cleanup/join → release UOW → close G_finalize → terminal |
| FINALIZE после Written/Failed | Проверить resources_closed; acquire новый G_finalize. Не повторять acquire G_write и не закрывать чужой guard |
| Failed FINALIZE | Прекратить новый dispatch, join всех принятых cleanup futures → close собственного G_finalize → resources_closed → Failed(round). Reconciliation начинает с нового guard только после этого terminal |
| Seal | Физических IO и gate нет; session mutex сериализует seal commit с установкой closing. Оно не ждёт WRITE внутри mutex: Written и resources_closed проверяются при acceptance. Local/full/hold и fresh SQL predicates сохраняют защиту immutable final |

Gate acquisition cancellation также имеет resource epilogue: если ОС уже выдала guard, именно acquisition task его закрывает до resources_closed. Dispatcher session mutex никогда не удерживается при gate/join/physical IO; Seal держит его только на коротком SQL UOW, не вызывает physical worker.

Неопределённый результат Unlock/Close или join, который не завершён, НЕ выдаёт resources_closed. Невозможность подтвердить close при terminal OS error помечает host/root poisoned: запрещены новые gate acquisitions и IO commands всего root, recovery имеет RESTART_HOST_THEN_RECOVER; существующие workers остаются owned до завершения/host termination. Ни release row, ни completed cleanup не разрешают acquire возможного собственного lock. Долгий ещё работающий join остаётся Running, не Failed. Этот fail-closed случай отличается от обычного cleanup/SQL failure, где guard успешно закрыт и доступен ReconcileFinalize.

Tests: WRITE удерживает gate, concurrent FINALIZE ждёт именно terminal WRITE, а не lock; WRITE failure на каждом syscall; FINALIZE failure до/после release commit; повторные ReconcileFinalize(r); delayed duplicate r после r+1; guard close fault → poisoned без повторного acquire. Проверять максимум одного guard owner и ноль wait-on-own-lock, а не только eventual completion.

## 11. Identity и reserve: точные зависимости

`reserve_stage(view)` использует один existing write UOW: decode integrity → exact acquisition/host view → no P/X → current operation admission/fence → `SqliteArtifactCatalog.reserve_in_scope(scope,binding.lease,binding.artifact)` → commit. Scoped catalog primitive извлекается из existing reserve без копии predicates и без собственного commit. Legacy reserve сохраняется только для legacy callers. Test interleavings: P-before-reserve, X-before-reserve, reserve-before-P, lost reserve ACK; во всех случаях ни новый hold, ни catalog mutation после P/X. Fresh check только до отдельно коммитящего reserve запрещён.

Identity transport — обязательная proposed dependency, реализуется перед запуском данного parent. `CallSuccess.identity: ExecutionIdentity` выдаётся Engine. Fresh payload `StageFreshInput(kind=FRESH, lease: OperationLeaseRef, artifact: ArtifactRef, prepared_source: ExecutionIdentity)` НЕ содержит binding/stage_id; registered input — конкретная оболочка `StageRouteInput(request=StageFreshInput(...))` (§12.3). Lease/ref поступают из зарегистрированных производителей; declared dependency prepared_source проверяется Engine. Единственный issuer binding.stage_id — fresh StageRecoveryWorkflowNode.start по своему begin CALL origin. Concrete content type C и prepare/stage target зарегистрированы в test fixture; production target не назначается.

`StagePreparedBinding` реализует proposed `InputBinding[PrepareOutput[C], StageBindingParameters, StageInput[C]]`; `StageBindingParameters(permit)` переиспользуется из identity-плана. build кладёт `output.value` непосредственно в `StageInput.request.prepared`, `parameters.permit` в request.permit. Parent всегда создаёт BoundInput(binding, source=state.prepared_source, parameters=StageBindingParameters(permit)). Ни input, ни continuation не содержат независимый serialized prepared.

На checkpoint сохраняется prepare terminal один раз и BoundInputCheckpoint(binding_id/version, exact source identity, parameters_json). На restore: registry/version check → единственный decode+полная validation prepare terminal → source success/attempt/revision/visibility check → build bound input → полная validation без замены protected objects → catalog/outcome ссылки на тот же объект. Missing/stale/foreign source, cycle, contract mismatch — RestoreFailure до dispatch. Successful prepare не повторяется. При новых generations source остаётся исходным; другой prepare attempt не подставляется по NodeId. Producer удерживается в primary graph пока существует незавершённый route, bound input ИЛИ retained dependency завершённого RouteSuspended (§12.1). Это retention, не дополнительное разрешение чтения. Invalidation producer инвалидирует потребителей и отклоняет resume, не пересобирает prepared.

Граница host НЕ переносит PreparedArtifact и Python identity. Public Artifacts stage и owning writer остаются в DAG worker process; `stage.request.prepared is prepare.output.value` и `.content is prepare.output.value.content` обязательны после admission. Новый `ArtifactPhysicalEncoder.encode(prepared, registered_contract) -> bytes` внутри Artifacts вызывает ровно существующий format encoding на этом content (pure, без IO); format/hash/size проверяются по descriptor. Internal WriteCommand получает encoded bytes. Host backend принимает bytes и ref, выполняет physical validation/placement; не вызывает prepare/stage, не декодирует второй PreparedArtifact и не требует cross-process `is`. Это явное сужение host до physical backend, а не отмена public identity. Для format codec, где backend сейчас совмещает encoding и запись, выделяется pure encode primitive с тем же алгоритмом; semantic consumer decoding не переносится.

`ArtifactPhysicalEncoder` (application/artifacts/staging/physicalEncoder.py) зависит только от registered format codec; отказ при SQL/IO, изготовлении нового PreparedArtifact или повторном prepare. HostWriteJob получает только physical bytes и existing ArtifactRef, не Engine producer identity. Tests: runtime-created bytes и frozen model с always revalidation через public run/restore; assert is на stage и encoder input; exact encoded bytes на host, отсутствие PreparedArtifact decoder в host; после host reboot новый generation использует тот же restored producer внутри нового caller lifetime.

### 11.1. Точное подключение общего BLOB backend: отдельная internal capability

Выбран ровно один вариант: `HostBlobPhysicalAdapter` над тем же зарегистрированным `ContentAddressedBlobBackend`. Existing `ArtifactBackend.write(reservation,content)` и constructor BLOB backend НЕ меняют свой legacy контракт. Host jobs никогда не вызывают write/verify legacy entrypoints. Это не второй backend по другому format key и не fallback. Новая capability и adapter — proposed; конкретный production format/workflow не выбирается.

`IStagePhysicalBackend` — ABC в `application/artifacts/contracts/stagePhysicalBackend.py`, только Artifacts internal contract. Свойства: `backend: ArtifactBackend[bytes]`, `contract: ArtifactFormatContract[bytes]`, `root_identity: EntityUid`, `attempts: IStageAttemptStore`, `gate: WindowsBlobEffectGate`. Методы:

- `async write_encoded(view: HostWriteView, local: StageLocalWriter, reservation: StagingReservation, encoded: bytes, guard: BlobEffectGuard) -> None`.
- `async verify_encoded(view: HostWriteView, local: StageLocalWriter, reservation: StagingReservation, guard: BlobEffectGuard) -> None`.
- `async cleanup_owned(view: HostFinalizationView, guard: BlobEffectGuard) -> None`.

HostWriteView/HostFinalizationView/StageLocalWriter/guard — уже определённые internal issued resources, не новые public DTO. Finalization view адресует exact binding/generation/claim и не требует synthetic reservation для no-link. Capability не приобретает/освобождает local/full claims, gate, SQL transaction или session; не выполняет seal/release. Проверяет issued guard текущего job/root и correlation ресурсов; до каждого batch вызывает existing proposed `attempts.assert_effect_allowed(view,guard)` (короткий scope, без вложенного IO). Затем вызывает общий физический primitive и дожидается всех accepted IO. Mode WRITE/FINALIZE определяется типом issued view и store, не boolean от caller. OS/codec/invariant ошибки идут в прежние категории; capability сама их не переводит в RPC success.

`HostBlobPhysicalAdapter` в `storage/artifacts/physicalHost/blobPhysicalAdapter.py`:

`__init__(backend: ContentAddressedBlobBackend, *, attempts: IStageAttemptStore, gate: WindowsBlobEffectGate, root_identity: EntityUid)`.

Constructor не создаёт backend/leases/registry/gate: требует DI instances. Проверяет backend canonical root == gate canonical root, root_identity соответствует installation binding, backend.write_admission и attempts имеют тот же existing Snapshot access/registry authority graph. Не сравнивает Python object identity между процессами. `adapter.contract is backend.contract`; adapter.backend неизменяем. Guard принадлежит только host job согласно §10.2; adapter никогда не acquire gate, поэтому не может ждать собственного lock.

`ContentAddressedBlobBackend(root: Path, contract: ArtifactFormatContract[bytes], leases: IArtifactLeases)` сохраняется. В том же классе добавить **private physical primitives**:

- `_write_encoded_batch(ref: ArtifactRef, encoded: bytes, temp_claim_id: EntityUid) -> None` (async): exact BLOB ref, bytes type/size/hash; deterministic temp по claim; write/fsync/place; cleanup своего temp; join всего IO до возврата/raise. Не вызывает contract.encode/leases.writer/leases.assert_writable, не владеет SQL/gate. Вызывается только adapter после checks.
- `_verify_encoded_batch(ref: ArtifactRef) -> None` (async): existing `_verify(_path(ref),ref)` через joined `_io`, без повторного encoding и claims.
- `_cleanup_stage_batch(ref: ArtifactRef, temp_claim_id: EntityUid) -> None` (async): deterministic exact temp only, missing_ok, contained path, joined IO. Не удаляет final path.

Общие `_path/_contained/_place/_verify/_sync_directory` используются тем же backend instance. Из `_temp` выделить `_write_temp_file(path,data,ref)` с write/flush/fsync/verify, без выбора random/deterministic identity. Legacy `_temp` сохраняет mkstemp и legacy cleanup; authorized `_write_encoded_batch` создаёт exclusive deterministic path и использует общий writer. No truncate существующего temp; stale preexisting temp в WRITE — invariant failure, только FINALIZE вправе удалить после P/drain. Каждый authorized finally работает внутри вызова с held guard и joined IO. Adapter не копирует path/hash/placement алгоритм. Legacy public write по-прежнему кодирует content и владеет своим local claim; для authorized пути эта entrypoint недоступна по job dependencies.

Registry конкретно расширяется двумя методами:

Первый вызывается ПОСЛЕ existing register(contract,backend). Проверяет `_bindings[key][0] is contract`, `capability.contract is contract`, `capability.backend is _bindings[key][1]`, kind BLOB/content_model bytes, один capability на key, совпадение root/authority/gate с host composition. Второй делает registry.validate(ref), проверяет supported version и наличие capability; отсутствие — deterministic configuration failure ДО reserve/IO, никакого resolve(...).write fallback. Python `is` contract между процессами не обещается и не проверяется. Проверки model identity из §11 относятся к общему proposed Engine transport и выполняются отдельно на test content backend; этот adapter НЕ объявляется реализацией SQL_ROWS physical storage. Другой physical capability требует собственного контракта до activation. Это не выбор production workflow.

## 12. Конкретный recovery parent без production workflow

Proposed `StageRecoveryWorkflowNode` в `application/engine/nodes/artifacts/stage/stageRecoveryWorkflowNode.py`: одна resumable orchestration node семейства Artifacts, child leaf targets begin/stage/recover. Registered targets/contract versions заданы composition; no service dependencies. Нода не вызывает reserve/host/SQL, не реализует admission. Test registration имеет фиксированные keys ниже; production graph не выбирается. Engine передаёт CallOrigin согласно SR-02.

State POJO в `dataModel/engine/dag/stageRoute.py`: конкретный `StageRouteState` с полем `phase`, содержащим strict discriminated union WaitBegin/WaitStage/WaitRecover (§12.3). FINISHED не хранится как continuation, используется terminal. Варианты state и отдельный terminal suspension payload:

- `WaitBegin(kind=WAIT_BEGIN, binding, prepared_source, expected: ExpectedCall)`.
- `WaitStage(kind=WAIT_STAGE, binding, prepared_source, permit, expected)`.
- `WaitRecover(kind=WAIT_RECOVER, binding, prepared_source, observed_generation: positive int, expected)`.
- `RouteSuspended(kind=SUSPENDED, binding, prepared_source, observed_generation: positive int|None, failed_call: ExpectedCall, failure_source: ExecutionIdentity)` — terminal output, НЕ runnable continuation. failure_source адресует primary failed child InvocationRecord из CallRuntimeFailure.diagnostic_ref; envelope не копируется в parent terminal (§14).

`ExpectedCall(key: CallKey, caller_step: nonnegative int, node_id: NodeId, contract_id: ContractId, version: ContractVersion)` — сериализуемый адрес ожидаемого CALL; существующие identity-типы и их strict validators переиспользуются. Runtime TargetSignature/CallTarget и Python-классы в этот POJO не входят; порядок сопоставления с регистрацией — §12.4. Exact child ExecutionIdentity проверяет Engine по caller links; parent не придумывает child ID. No optional permit в WaitBegin/WaitRecover. `StageRouteResult` — конкретная модель с полем `result`, union вариантов `RouteConfirmed(kind=CONFIRMED,binding,ref,completed_generation)` | `RouteRefused(kind=REFUSED,refusal: StageRecoveryRefused)` | RouteSuspended(kind=SUSPENDED). Cancellation остаётся Engine cancelled terminal, не новый успех/result. Declared errors остаются объявленными NodeError через PythonNodeError; не RouteRefused.

Fresh start(input: StageRouteInput,origin): request=input.request должен быть StageFreshInput; source должен быть разрешённым declared prepare dependency; вычислить stage_id по origin и key `begin` РОВНО ЗДЕСЬ, построить StageBinding(stage_id,request.lease,request.artifact); сохранить StageRouteState(phase=WaitBegin(...)) и единственный Call(key=`begin`, target=begin, StageBeginInput(binding)). CAS/checkpoint сохраняет input/state/call links до begin. Restore не вызывает fresh start для уже сохранённого WaitBegin. Resume entry всегда использует сохранённый binding, не эту ветку start. Таблица ниже сокращает оболочки: Wait* означает state.phase, Complete Variant означает Complete(StageRouteResult(result=Variant)); каждый исходящий Call.state — StageRouteState(phase=Wait*(...)), никогда union/голый variant.

| State + event | Следующий NodeStep и точный key |
|---|---|
| WaitBegin + Allowed(p) | Проверить p.binding == state.binding, p.generation==1; Call `stage/1` с BoundInput(source,parameters=p), WaitStage(p, expected для текущего origin.step) |
| WaitStage(g) + Success(ref) | Complete RouteConfirmed(binding,ref,g); ref обязан совпасть с binding.artifact |
| WaitStage(g) + CallOutcomeUnknown | Call `recover/g`, StageRecoveryInput(binding,g), WaitRecover(observed_generation=g) |
| WaitStage(g) + RuntimeFailure(category OUTCOME_UNKNOWN или UNKNOWN_COMMIT) | Тот же явный `recover/g`; cause сохраняется в child failure record. Это control recovery, не stage retry |
| WaitRecover(g) + Allowed(p) | p.binding exact; p.generation в {g,g+1}; Call `stage/p.generation`, WaitStage(p). g допустима только unconsumed permit по owning result; parent сам consumption не выводит |
| WaitBegin/WaitRecover + Confirmed(c) | Complete RouteConfirmed(binding,c.binding.artifact,c.completed_generation) |
| WaitBegin/WaitRecover + Refused(r) | Complete RouteRefused(r) |
| Любой state + declared CallFailure(e) | PythonNodeError(e) unchanged; registration parent включает тот же union owning errors |
| Любой state + CallCancelled | Engine cancelled, без нового child |
| Любой иной CallRuntimeFailure | Complete RouteSuspended с failure_source=result.diagnostic_ref; primary exact envelope остаётся в child record, доступном checkpoint closure; никакого автоматического stage/control retry по exception class name |

Begin с RUNNING lost outcome восстанавливается Engine RETRY exact input; recover также RETRY exact input. Это replay transport interrupt, не retry declared failure. Для runtime failure begin/recover — RouteSuspended; subsequent explicit resume требует отдельного пользовательского/верхнего DAG решения, не скрытого цикла parent. После PhysicalHostRestartRequired terminal suspended сохраняет exact operand для явного возобновления через НОВЫЙ route-entry contract `ResumeStageRoute(suspended_source: ExecutionIdentity)` в той же parent registration. Вход строится только после declared dependency mapping §12.1; одна переданная identity доступа НЕ даёт. Из validated suspended output: если observed_generation есть — первый CALL recover/g; если её нет — begin с сохранённым binding. Stage_id не пересчитывается. Такой вход запускает только явный caller внутри того же execution; автоматический service reboot не вызывает DAG. Old terminal остаётся historical. Cross-execution перенос этим контрактом не допускается.

Одинаковый key `stage/g` в разных parent steps не означает повтор одного CALL: полный адрес включает parent invocation/step. Право на такой новый CALL даёт только новое Allowed; после consuming g и replay старого Allowed owning acquire откажет без IO. Checkpoint хранит WaitStage и accepted CALL атомарно: crash до accept повторяет тот же event/step/key; crash после accept ждёт уже записанного child. Переход в WaitRecover/WaitStage новой generation увеличивает step штатным Engine переходом, не вручную.

`resume` сопоставляет ExpectedCall со своим статически объявленным target по §12.4, затем получает outcome через CallResults.get(expected.key,target); Engine дополнительно проверяет caller_step и child binding. Старое событие stage/g после сохранённого WaitStage(g+1) не является допустимым resume event: delivery layer отбрасывает уже consumed event по durable caller-step/child links; если его всё же передали в parent — engine contract failure до создания Call. Отдельного mutable last-event registry нет. Два event delivery до checkpoint строят одинаковый NodeStep; accept проверяет exact state/input/source/permit. Concurrent parent owners отсечены existing claim/revision CAS. Test: crash до/после каждого accept и replay old event после generation change.

Cancellation operation — соседняя уже предложенная DAG цепочка Q5/Q6, не внутренний цикл StageRecoveryWorkflowNode. Engine cancellation parent не означает OperationCancelled. Caller операции явно делает close → inventory/finalize → cancel; ошибки и persisted operands сохраняются через тот же transport §13. Это сохраняет один уровень ответственности parent и не добавляет production workflow.

### 12.1. Explicit resume: declared dependencies и retention

Это конкретная proposed дельта Engine dependency mapping, а НЕ расширение visibility по наличию ExecutionIdentity. Модули: `application/engine/contracts/invocation/resumeDependencies.py` (статическая регистрация) и `dataModel/engine/dag/invocations/resumeDependencies.py` (wire edges). Production workflow не выбирается; test graph регистрирует те же правила и роли caller.

`StageRecoveryWorkflowNode` имеет обязательный declared input dependency slot `prepared`, тип `PrepareOutput[C]`, exact target/version. Fresh dispatch caller должен легально видеть prepare через собственный returned CALL либо declared dependency; `InvocationCoordinator.accept` сохраняет edge `(consumer invocation, slot='prepared', source=exact prepare ExecutionIdentity)` вместе с route input. Доступ parent к prepared определяется этим edge, не input.prepared_source; они обязаны совпасть. BoundInput stage child разрешён из declared dependency parent и наследует её provenance штатным accept. Передача identity без edge — contract failure.

Статическая регистрация `ResumeDependencyMapping` содержит contract_id/version, source_target=StageRecoveryWorkflowNode, terminal_variant=RouteSuspended, destination_target=тот же StageRecoveryWorkflowNode/resume-entry, inherited_slots=('prepared',), same_execution=True. Никаких callbacks, domain IO или произвольных путей JSON. Конкретные свойства suspension читает typed validation этого зарегистрированного варианта, а разрешение доступа берётся из graph edges. Registration входит в registry fingerprint.

`ResumeDependencies(mapping_id, mapping_version, suspended_source: ExecutionIdentity)` — proposed typed dispatch metadata рядом с input, не authority token. Для нового CALL caller обязан легально видеть suspended_source как собственный returned CALL или declared dependency read. Нельзя предъявить terminal произвольной чужой invocation. Дополнительное разрешение перенести именно slot prepared даёт статическая ResumeDependencyMapping; оно не выдаёт caller общий доступ к payload producer.

`InvocationCoordinator.accept_resume_dependencies(dispatch)` перед созданием child:

1. Проверяет caller visibility suspended_source по прежнему правилу, same execution и exact invocation/attempt/revision, source terminal SUCCEEDED с output-вариантом RouteSuspended; наличие error/другого terminal отвергает input.
2. Проверяет mapping registration, source/destination target versions. Из authoritative source invocation читает persisted declared dependency edge prepared. Этот edge должен существовать со времени initial acceptance; нельзя восстановить его из suspension DTO. Проверяет, что edge.source == suspended.prepared_source, producer SUCCEEDED, тип/версия exact и producer не invalidated.
3. Создаёт новой parent invocation два declared dependencies: `suspended` → exact suspended_source, `prepared` → source прежнего edge. Это явно разрешённый registered dependency mapping, не обращение к чужому CALL. Строит bound input через `ResumeStageInputBinding` (§12.2): runtime `StageRouteInput(request=ResumeStageRoute(suspended_source, suspended=validated_source_output.result))`. Source output обязан быть StageRouteResult с result типа RouteSuspended. Parent получает значение через обычный start(input,origin), без dependency view; prepared передаёт следующему child через BoundInput по унаследованному edge.
4. Сохраняет input, оба edges, caller links и continuation в одном existing accept/checkpoint CAS ДО запуска новой parent. При replay те же sources/mapping/parameters обязательны. Restore валидирует весь путь provenance и retention edges до build/dispatch. Missing/mismatch/foreign source — RestoreFailure; live dispatch — CONTRACT failure. Никакого fallback по ref/NodeId.

Новая parent далее выдаёт BoundInput stage из СВОЕЙ declared prepared dependency, поэтому исходное правило identity-плана §5.3 соблюдается. Старый parent CALL не считается CALL нового parent. Для повторного suspended после resume действует та же процедура; зависимость остаётся на исходный prepare attempt, не копию. Верхний orchestration caller вправе явно resume после restart только внутри восстановленного того же execution и при legal visibility terminal результата. Новый независимый execution не импортирует граф и не получает эти права. Это предел контракта, не повод повторить prepare.

**Retention:** при фиксации RouteSuspended `InvocationCoordinator.finish` добавляет в его existing checkpoint record typed `retained_dependencies: tuple[RetainedDependency,...]`, где `RetainedDependency(slot='prepared', mapping_id, mapping_version)` НЕ содержит source identity. Это retention-маркер существующего declared dependency edge данного record, а не второй edge с независимо изменяемым source. Finish атомарно сохраняет terminal и маркер в одном checkpoint, проверяя наличие exact edge. Нет окна «terminal сохранён, producer уже удалён». Failure этого save не выдаёт durable suspension ACK. Полный инвариант §14.

`CheckpointCodec.encode`, graph pruning и ExecutionSnapshotService обязаны включать transitive closure retained_dependencies независимо от terminal status route/execution. Пока сохранён checkpoint с RouteSuspended, producer terminal, его contract/version и необходимые provenance records сохраняются без TTL/pruning; новый resume также удерживает их своими dependency edges. После успешного resume старый suspension остаётся historical и его retention edge не удаляется автоматически. Минимальная политика намеренно проста: освобождение только при явном удалении всего execution/checkpoint существующей storage retention policy, которое одновременно прекращает возможность resume. Отдельного GC/нового retention service не вводится. Автоматическое удаление completed execution, пока в нём есть suspended edge, для этой регистрации запрещено; storage composition обязана поддержать это до activation.

Retention даёт только наличие данных, не visibility и не immunity к domain/engine invalidation. Replan может сделать producer invalid; record сохраняется для диагностики, но accept_resume_dependencies отклоняет resume. Explicit execution deletion оставляет обычный execution-not-found, не synthetic PreparedArtifact. Чтение historical terminal как результата без resume не открывает producer внешним callers.

Ответственность: ResumeDependencyMapping — immutable registration без IO; InvocationCoordinator — единственная проверка/запись graph edges; CheckpointCodec — единственный encode/decode с closure; ExecutionSnapshotService — ссылки на те же восстановленные producer objects; ExecutionStore — существующий blob/CAS и retention, без domain mapping. Нарушение любого из пунктов (DTO как grant, JSON clone prepared, отсутствующий retained producer, cross-execution graft) — отказ приёмки.

Проверки: terminal suspended → pruning → cold restore → explicit resume с legal caller; illegal caller с правильным DTO; terminal без edge; подмена source attempt; replay resume accept до/после CAS; повторное suspension новой parent; invalidated producer; explicit deletion; никакого повторного prepare; stage.prepared is restored producer после обоих последовательных resume. Эти тесты дополняют identity-план; его proposed codec/bindings не объявляются реализованными.

### 12.2. Получение suspended output через конкретный bound input

Нормативное уточнение всех сокращений `ResumeStageRoute(suspended_source)` выше: это request/address до admission, НЕ готовый runtime input parent. Payload — `ResumeStageRoute(kind=RESUME, suspended_source: ExecutionIdentity, suspended: RouteSuspended)` в `dataModel/engine/dag/stageRoute.py`. Зарегистрированный input parent — конкретный класс `StageRouteInput`, его поле request содержит discriminated union StageFreshInput/ResumeStageRoute (§12.3). `ResumablePythonNode.start(input,origin)` получает StageRouteInput обычным аргументом. Внутри resume-entry ветки `saved = input.request.suspended`; binding/generation/prepared_source берутся из saved. При наличии generation parent создаёт WaitRecover/recover CALL, иначе WaitBegin/begin CALL. Failure_source сохраняет корреляцию диагностики, но для выбора этой явно запрошенной ветки читать envelope не требуется. Никакого read(view), lookup по identity или повторного вызова старого parent в start нет.

`ResumeStageInputParameters(suspended_source: ExecutionIdentity)` — named parameters POJO. `ResumeStageInputBinding` в `application/engine/nodes/artifacts/stageResumeInputBinding.py` реализует proposed `InputBinding[StageRouteResult,ResumeStageInputParameters,StageRouteInput]`, contract_id=`artifacts.stage-resume-input`, version=1. `build(output: StageRouteResult,parameters) -> StageRouteInput` требует exact RouteSuspended в output.result, возвращает `StageRouteInput(request=ResumeStageRoute(suspended_source=parameters.suspended_source,suspended=output.result))`. binding.input_type и destination target.input_type — один класс StageRouteInput; binding.source.output_type — StageRouteResult. Только typed constructors/прямая передача payload; никаких IO, visibility checks, domain policy или encoding. Проверки источника выполняет coordinator до build.

Explicit caller передаёт Call.input = BoundInput(binding=ResumeStageInputBinding, source=suspended_identity, parameters=ResumeStageInputParameters(suspended_identity)) и metadata ResumeDependencies с ТЕМ ЖЕ source. `accept_resume_dependencies` проверяет равенство трёх source references и разрешения §12.1, устанавливает declared edges, затем обычный bind-path строит input. Нельзя отдельно передать literal ResumeStageRoute с вложенным payload: эта registration принимает RESUME только с указанным bound input/mapping. Forged literal → CONTRACT failure до start. Fresh registration сохраняет ранее описанный путь и единственного issuer stage_id.

Checkpoint хранит BoundInputCheckpoint и параметры, а не копию suspended terminal внутри input. Restore: восстановить source terminal StageRouteResult один раз → проверить provenance/edges/mapping → build input → полная structural validation с сохранением принятого immutable source → NodeRunner передаёт record.input в start. `input.request.suspended is restored_source_terminal.result` — тестовый критерий; live source передаётся без decode. Duplicate source identity в parameters служит корреляции и обязана совпадать с BoundInput.source; она не источник authority. Весь bound StageRouteInput не хранится независимым JSON input.

`resume(state: StageRouteState,event,origin)` для уже запущенной parent не требует этого input/view: всё необходимое для продолжения уже в state.phase (WaitBegin/WaitRecover/WaitStage); prepared_source там — адрес для BoundInput, не обязанность прочитать content. Identity остаётся у primary producer graph. Тестовый callable parent получает только input/origin либо state/event/origin, без скрытой зависимости от engine context, и проходит cold resume с зарегистрированным binding.

### 12.3. Registered input/output/continuation: только concrete BaseModel

Сверены existing CallTarget.__post_init__, NodeContract.__post_init__, ContinuationContract.state_type и NodeStep: TypeAdapter(type[BaseModel]) требует класс модели, generic параметры NodeStep/continuation ограничены BaseModel. Ради route union эти API НЕ расширяются. Proposed CallOrigin/BoundInput из прежнего плана остаются отдельными дельтами; они не разрешают регистрировать union вместо model class.

Все три оболочки — именованные негeneric concrete BaseModel в `dataModel/engine/dag/stageRoute.py`, config strict=True, frozen=True, extra='forbid', revalidate_instances='always':

| Класс | Полное owning поле |
|---|---|
| StageRouteInput | `request: Annotated[StageFreshInput | ResumeStageRoute, Field(discriminator='kind')]` |
| StageRouteResult | `result: Annotated[RouteConfirmed | RouteRefused | RouteSuspended, Field(discriminator='kind')]` |
| StageRouteState | `phase: Annotated[WaitBegin | WaitStage | WaitRecover, Field(discriminator='kind')]` |

Каждый variant — отдельный strict/frozen concrete BaseModel с обязательным kind: Literal соответствующего значения. Union существует только как annotation поля. ## 13. U6: durable errors и точный parent outcome

AS-IS NodeRunner.run_resumable сохраняет для обычного exception diagnostic.message = type(exc).__name__; CallRuntimeFailure содержит только diagnostic_ref. Этого недостаточно. Предлагается один generic Engine wire carrier, не новый Artifacts exception enum и не второй журнал.

`FailureEnvelope` в нейтральном `dataModel/transport/failureEnvelope.py` (§15.2); прежнее размещение в Engine WITHDRAWN:

- `schema_version: Literal[1]`, `category: Literal[INFRASTRUCTURE,UNKNOWN_COMMIT,OUTCOME_UNKNOWN,CONTRACT,UNEXPECTED]`.
- `owner_contract_id: strict nonempty str`, `owner_contract_version: strict positive int`, `payload_json: str` — identity версии owning failure schema, не Engine node contract; exact validated owner payload из зарегистрированного failure codec. Никаких импортов Engine identity types, pickle/type-name import.
- `causes: tuple[FailureCause,...]`; `FailureCause(index: nonnegative int, type_name: str, message: str, relation: Literal[CAUSE,CONTEXT,SUPPRESSED], parent_index: nonnegative int|None, os_errno: int|None, winerror: int|None)`. Индексы уникальны, graph acyclic; explicit cause и suppressed cancellation сохраняются. Все обязательные поля, nullable только указанные.

Это diagnostic projection exception chain, не обещание восстановить Python traceback/exception object identity. Тексты/коды сохраняются целиком в пределах existing checkpoint payload admission limits; превышение лимита — persistence failure без ложного terminal ACK, никакого silent truncation. Exception cycle обнаруживается codec и выдаёт CONTRACT failure с diagnostic chain fault; не бесконечная сериализация. Category и owner payload задаёт зарегистрированный codec, Engine не распознаёт Artifacts по имени типа.

Artifacts owner payload `StageInfrastructureFailure` в `dataModel/artifacts/staging/stageFailure.py`: `binding: StageBinding`, `generation: positive int|None`, `site: Literal[BEGIN,ACQUIRE,RESERVE,WRITE,VERIFY,SEAL,FINALIZE,RELEASE,RECOVER,HOST_CONNECT]`, `root_identity: EntityUid`, `command: Literal[WRITE,SEAL,FINALIZE]|None`, `recovery: Literal[EXACT_RECONCILE,EXPLICIT_RECOVER,RESTART_HOST_THEN_RECOVER,STOP]`. Recovery field описывает допустимое действие owning контракта, не запускает его. Host error и client error используют тот же payload/codec, не две копии POJO.

`NodeContract.failure_codecs: tuple[FailureCodec,...]` — proposed immutable registration, входит в fingerprint. `FailureCodec` в `application/engine/contracts/invocation/failureCodec.py`: contract_id/version, payload_type, `encode(exception, input, identity) -> FailureEnvelope | None`, `validate(envelope) -> None`; pure conversion, без IO/service/callback orchestration. Artifacts codec находится в Artifacts, dependency Engine только protocol. Не поддержанный exception → generic Engine UNEXPECTED с пустым typed `UnexpectedFailureDetails` payload; type_name/message хранятся только в корневом FailureCause, не повторяются в payload. Ошибка самого codec → CONTRACT failure, original exception остаётся cause. Engine cancellation обрабатывается до codec; secondary cleanup/unknown exception с cancellation context кодируется как failure, не как успешная отмена. Сопоставление с ExecutionDiagnostic и единственные первичные факты — §14.

Exception cancellation context и cancellation intent различаются: `FailureCause(type_name='CancelledError',...)` отражает реально пойманный exception, без копии user request message/source/reason/timestamps. Эти event поля остаются только в existing CancellationRequest/ExecutionDiagnostic. Codec не добавляет в exception message текст cancellation request. При чистой cancellation — existing CallCancelled/diagnostics, envelope отсутствует. При cleanup error после cancellation — FAILED+envelope с exception context; ранее observed cancellation event остаётся event cause, но не превращает failed outcome в CANCELLED. Таким образом cancellation не записывается второй раз как конкурирующий terminal.

Existing diagnostic.message для иных legacy событий не меняется. В новом route он не является источником error policy: только envelope.category и validated owner payload. Read-only UI может вычислять отображаемую строку из failure_source, но не сохраняет копию как primary diagnostic. Runtime transport host→client→NodeRunner доставляет envelope без нового wrap/повторного кодирования уже decoded remote error; новый локальный transport failure имеет собственный primary exception и causal link к прежнему outcome только если он действительно получен. Недоставленный remote cause не придумывается.

`StageRouteTerminalBinding` извлекает failure_source/failed_call и возвращает generic ChildFailureReference (§15.1). InvocationCoordinator.finish проверяет exact failed child/caller links/runtime_failure по этой metadata, без знания RouteSuspended. Encode/restore closure удерживает primary failed record и его existing diagnostics; missing/mismatched reference — RestoreFailure. Ссылка имеет тип существующего ExecutionIdentity; новый error ledger/id allocator не нужен. `CallRuntimeFailure.failure` — runtime projection того же record, diagnostic_ref — его correlation. После restore envelope decode один раз; parent классифицирует его при получении события. Для explicit resume envelope из start не требуется (§12.2).

### Единственный источник dependency identity

Proposed declared edge `(consumer ExecutionIdentity, slot, source ExecutionIdentity, target/version)` — единственное authoritative место адреса producer для данного slot. В каждом consumer slot уникален. Он immutable после accept; replan создаёт новую consumer identity/invalidates binding, не переназначает edge старой invocation.

`RetainedDependency(slot,mapping_id,mapping_version)` — marker необходимости хранить этот edge и transitive producer closure после terminal, НЕ второй edge. Source из него удалён (§12.1), поэтому две identity нельзя рассогласовать. Validator требует: marker.slot существует в declared edges того же record; mapping зарегистрирован и допускает этот slot/terminal variant. Маркер без edge, duplicate marker или несовместимый mapping — invalid checkpoint. Pruning начинает обход marker → existing edge → producer; retention не выдаёт visibility.

`prepared_source` в route input/state/suspended, `BoundInput.source`, `DependencyRead.result` — ссылки/наблюдения на тот же факт, не независимые authority. На accept/build/finish/restore проверяется exact equality с source declared edge, включая execution/invocation/attempt/revision. `DependencyRead` остаётся evidence совершённого разрешённого чтения, не объявлением разрешения и не retention policy. Descriptor equality/одинаковый NodeId не разрешают repair mismatch. Typed ResumeDependencyMapping переносит source из исходного authoritative edge в новый edge атомарно (§12.1); DTO source служит только проверке корреляции.

Повторение identity в ссылках допустимо как referential identity, как FK к одному факту; оно не создаёт параллельной изменяемой семантики или второго POJO для producer result. StageBinding во failure payload — контекст отказа существующего owning типа, не новая модель binding; persisted stage authority по-прежнему Artifacts rows. Новых mirrors field/logic errors нет. Исключение на дублирование POJO не запрашивается: все роли выше различны, а прежняя избыточная source в RetainedDependency и копия envelope в RouteSuspended удалены из proposal.

Проверки приёмки: failure с cause/context/OS code и cancellation event проходит round-trip без копии exception в diagnostic; envelope хранится в одном primary record; suspended только ссылается на него; declared error не меняет категорию; marker без edge и mismatched route/source/read отклоняются; две generations и explicit resume сохраняют source exact attempt; pruning удерживает оба referenced producer/error records. Ошибка любого инварианта означает отказ, не автоматический repair. Проверки implementation ещё не выполнялись; изменён только архитектурный план.

## 15. Архитектурная коррекция: generic Engine, neutral transport, cutover

2026-11-27. Нормативное уточнение §§12–14: примеры с prepared/suspended/failure_source описывают конкретную регистрацию ноды, а не специальные ветки Engine. ### 15.1. Typed terminal binding вместо знания route в Engine

Один proposed `TerminalReferenceBinding[O: BaseModel]` в `application/engine/contracts/invocation/terminalReferenceBinding.py`: immutable contract_id/version/output_type, pure `project(output: O) -> TerminalReferences`. Это статически зарегистрированная typed projection, аналог InputBinding; не callback из checkpoint, не orchestration hook. Ранее blanket запрет callbacks в ResumeDependencyMapping означает запрет произвольных/сериализуемых callbacks, а не этого именованного pure binding. Binding не получает graph, scopes, services и не решает visibility или retry.

Generic `TerminalReferences` в `dataModel/engine/dag/invocations/terminalReferences.py` содержит `resume_mapping_ids: tuple[ContractId,...]`, `dependencies: tuple[DependencyReference,...]`, `failures: tuple[ChildFailureReference,...]`. DependencyReference(slot: strict nonempty str, source: ExecutionIdentity); ChildFailureReference(source: ExecutionIdentity, key: CallKey, caller_step: strict nonnegative int, node_id: NodeId, contract_id: ContractId, version: ContractVersion). Это временная validation projection, не вторая durable запись ссылок. Mapping versions берутся из fingerprint текущей immutable registration, не угадываются по latest.

`StageRouteTerminalBinding` в `application/engine/nodes/artifacts/stageRouteTerminalBinding.py` специализирует TerminalReferenceBinding[StageRouteResult]. Только он читает output.result: для RouteSuspended переносит prepared_source и failure_source/failed_call в generic references и объявляет зарегистрированный resume mapping; для прочих вариантов возвращает пустые references. Никаких IO, запуска CALL, проверки operation state или самостоятельного разрешения replay. Module/class роли принадлежат DAG family, не runtime Engine.

NodeContract содержит optional terminal_reference_binding, его identity/version входят в fingerprint. Отсутствующий binding означает отсутствие дополнительных terminal references, не эвристику по имени класса. NodeRunner структурно валидирует output; InvocationCoordinator.finish вызывает зарегистрированную projection и проверяет references по своему graph: dependency slot уже принадлежит invocation и source exact; failure указывает её exact child/key/step/target с runtime_failure. Затем одним checkpoint сохраняет terminal и существующие retention markers. Projection не пишет graph и не выдаёт authority. На restore та же projection после decode; mismatch — RestoreFailure до dispatch. Нельзя доверять metadata от caller вместо вычисления из принятого output.

ResumeDependencyMapping больше НЕ содержит terminal_variant и пути result/prepared_source/failure_source. Оно хранит source/destination target signatures, binding id/version, inherited slots и same_execution. accept_resume_dependencies требует SUCCEEDED source, mapping id в результате зарегистрированной projection, exact graph edges и caller visibility. Затем обычный зарегистрированный ResumeStageInputBinding строит typed input. Конкретные проверки варианта/полей §§12.1–12.3 принадлежат этим двум bindings. В Engine нет импортов stageRoute/Artifacts POJO, строковых проверок prepared/suspended и обращения к terminal.result. §12.4 также использует generic reference validation, не добавляет в codec разбор ExpectedCall.

RetainedDependency по-прежнему marker existing edge; TerminalReferences не сохраняется параллельно ему. Pruning/codec обходят generic edges/markers и проверенные failure references через зарегистрированную projection, не классифицируют RouteSuspended. Проверка: fixture второго, не-Artifacts output с иными полями использует те же Engine paths без их изменения; missing/foreign references отвергаются. Binding с IO либо специальная ветка в coordinator/codec — отказ архитектурной приёмки.

### 15.2. Один transport envelope без обратной зависимости host → Engine

Единственный модуль FailureEnvelope/FailureCause/UnexpectedFailureDetails — proposed `dataModel/transport/failureEnvelope.py`. Владелец — общие transport DTO, без зависимости от Engine, Artifacts, SQLite и Windows. Поля/категории §13 сохраняются, schema id/version являются локальными transport schema primitives. Обе стороны RPC и Engine импортируют этот один тип; старый proposed Engine-модуль не создаётся, alias-копия не нужна.

Единственный `FailureCodec[P: BaseModel]` находится в `application/transport/failureCodec.py`, вместо ранее предложенного Engine path: schema_id/version, payload_type, pure `encode(exception: Exception, request: BaseModel) -> FailureEnvelope | None`, `validate(envelope: FailureEnvelope) -> None`. ExecutionIdentity убран из codec signature: correlation invocation принадлежит Engine record, correlation stage — owning payload. Artifacts codec реализует этот protocol и формирует StageInfrastructureFailure; host factory и NodeContract получают явно зарегистрированные codecs из composition. Host не читает NodeContract и не импортирует Engine registration. Codec не выбирает следующий lifecycle transition.

NodeRunner выбирает codec из собственной immutable registration; host — из своего immutable набора transport codecs. Одинаковый schema id/version должен иметь одинаковый payload contract, конфликт отклоняется при assembly. Это две process-local регистрации одного контракта, не два error schema/журнала. Через RPC переносится один envelope; client валидирует его и передаёт через neutral `TransportFailure(Exception)` с полем envelope, без повторного encode causes. Engine распознаёт только этот общий carrier и проверяет schema по своей регистрации; неподдерживаемая схема — contract failure, не импорт по имени. Физический host полностью работоспособен без пакета Engine. Generic неожиданные исключения используют тот же neutral schema, не вторую engine-копию.

Приёмка: import graph neutral modules не ведёт в Engine/Artifacts; host test импортируется и выполняется без Engine; RPC→client→NodeRunner→checkpoint сохраняет category/payload/causes; declared NodeError остаётся отдельным путём. ExecutionDiagnostic и existing typed field/logic errors не перемещаются и не дублируются. Это изменение ownership proposed типов, не миграция существующих production error данных.

### 15.3. Authorized composition без legacy fallback

Existing inventory для точек границы: `core/container/packs.py` создаёт ContentAddressedBlobBackend и registry; `application/artifacts/staging/artifactStageWriter.py` вызывает backend.write и registry.verify; `artifactStaging.py` содержит TypedArtifactStager; `application/worldData/pack/encoding/preparedManifest.py` потребляет его. Эти существующие callers не объявляются перенесёнными или restart-safe. Production binding не выбирается в этой задаче.

| Composition / consumer | Разрешённые зависимости и путь | Критерий отказа |
|---|---|---|
| Authorized stage leaf → owning pipeline/writer | StageAttemptService/attempts + ArtifactPhysicalEncoder + ArtifactPhysicalClient; физические effects только WRITE/SEAL/FINALIZE host | Writer хранит legacy backend/catalog write dependency, вызывает backend.write/registry.verify как fallback либо продолжает локально при недоступном host |
| ArtifactPhysicalEncoder | Existing registry.encode, pure codec/descriptor checks | Физическая запись, reserve, выбор legacy backend для исполнения effects |
| Host jobs | Registered stage capability + attempts + job-owned guard; legacy backend доступен adapter только как владелец общих primitives | Legacy write/verify entrypoint в цепочке authorized job; второй local acquisition |
| Existing packs/TypedArtifactStager/preparedManifest и остальные legacy callers | До отдельного принятого cutover — existing legacy composition без выдачи HOST_BOOT_V1 permit и без обещания automatic recovery | Перенесённая операция всё ещё доступна тем же caller через старый route/factory как альтернативный writer |

Constructor authorized ArtifactStageWriter после cutover: `(attempts: IStageAttemptStore, encoder: ArtifactPhysicalEncoder, client: ArtifactPhysicalClient, log: ArtifactLifecycleLog)`; content contract передаётся через existing concrete binding pipeline/encoder, не второй registry writer. В target writer нет IArtifactWriteAdmission, IArtifactCatalog или ArtifactBackend field. Existing legacy TypedArtifactStager не переименовывается в authorized и не получает StageAttemptPermit. Если требуется поддержать обе composition одновременно, они используют явно разные concrete factories; optional client и режим fallback запрещены. Точная concrete format registration остаётся условием отдельной production activation, не исследовательского теста.

Перед activation выбранного binding обязательна конечная карта всех его callers/factories/routes: перенесённые и оставшиеся legacy с причиной. Для перенесённых сначала подключить принятый DAG route, затем убрать старую выдачу writer/вызов; не удалять независимый legacy workflow. Отсутствующая карта запрещает activation, но не требует сейчас миграции всех доменов. Registry наличие legacy backend не является разрешением его использовать authorized caller.

Проверки: отключённый host даёт infrastructure failure, local filesystem не меняется; spy legacy write/verify падает при любом вызове из authorized route; один full и один local acquisition; literal lease-only input отвергается authorized leaf; transferred factory не возвращает legacy writer; existing legacy fixture сохраняет прежний отдельный путь. Call-site/import audit дополняет тесты: одного заявления «нет fallback» недостаточно. Один root может содержать legacy claims; Publication по-прежнему учитывает их и не освобождает за них hold через HOST_BOOT_V1 finalizer.

Объём этой правки — спецификация границ и acceptance. Новый resolver, registry service, scheduler, error journal и альтернативный lifecycle не добавляются. Повторная полная приёмка и пользовательское решение о service/reboot остаются отдельными; runtime/code-go не заявляются.
