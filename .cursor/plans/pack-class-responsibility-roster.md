Уточнение 2026-11-13: metadata subject/output/bind конкретизированы в write-плане. PackPreparationService.describe_metadata принимает PackMetadataSubjectsInput и возвращает tuple[PackMetadataSubject, ...]; bind_metadata_provenance принимает PackMetadataProvenanceInput с tuple[PackMetadataProofBinding, ...]. Оба метода pure, не вызывают Source/prepare и не выбирают workflow. Describe выдаёт identity значения, не proof; bind сопоставляет exact subject и выполняет согласованный provenance admission. Прежняя форма entries из PackAssemblyProvenanceEntry не является вторым допустимым входом. Реализация и внешнее evidence mapping не объявляются завершёнными; PACK-METADATA-PLANNING не возвращается как блокер текущего Pack.

### Scope после выделения serialization/deserialization

PackPreparationIdentityCodec, PackActivationIdentityCodec и pure PackActivationRefusalCodec (mapping public refusal ↔ existing terminal) учитываются в [отдельном плане](pack-serialization-deserialization.md). Их зависимости — existing canonical codec, конкретные owning declarations и immutable records; effects отсутствуют. Признаки отказа: latest lookup, запись ledger внутри codec, стирание issue subtype, выбор следующего pipeline. В текущем Pack остаются точки вызова принятого binding; детали IDs/revision/READY reconstruction не являются повторным gate независимой работы.

Payload decoder обязанности остаются описанными в [binding roster](pack-payload-binding-roster.md): чистая проверка bytes/typed модели, сохранение owning semantics, без I/O/generation. JsonDecodeBudget — request-local structural preflight без schema/default policy, общий codec climate — один semantic путь для storage/read/prepare. Эти классы не становятся публичными операциями домена; детали сериализации проверяются отдельным планом, role/address/closure admission остаётся ответственностью Pack.

## Functions/модули — не выдуманные классы

[finish_pack_preparation](../../backend/app/application/worldData/pack/encoding/preparedManifest.py) — существующая async функция, не класс и не public pipeline. Её доказанная часть: stage, exact ref/digest, finish_preparation, проверка READY. Приёмка адаптации требует полного calculated closure; переданный other_members сам по себе не доказывает полноту.

[packManifestCodec](../../backend/app/application/worldData/pack/encoding/packManifestCodec.py), [manifest_format](../../backend/app/application/worldData/pack/encoding/manifestFormat.py), [climateFieldFormat](../../backend/app/application/worldData/pack/encoding/climateFieldFormat.py) — pure codecs/factories/contracts, не domain services. Decode не делает I/O, producer calls или latest lookup; строгие schema/budgets проверяются до потери информации. Существующая обратная проекция manifest в legacy модель не объявляется целевой реализацией.

Hydrology ROOT_FORMAT/SHARD_FORMAT и bounded codecs остаются owning форматами. Bytes contracts сами не выполняют semantic root/shard decode; включение нужной проверки — явная обязанность admission. Grade format/read descriptors уже заданы ТЗ, их registry implementation не создаётся повторно под другим именем.

## Итог обязательной проверки

Реестр делает явными public/internal/pure/I/O границы и критерии отказа для перечисленных классов. Три запрета DAG сохраняются: wrapper не выбирает следующую операцию, вызов не скрывается за worker/callback, публичные междоменные операции не вызываются напрямую. Internal admission callback — инфраструктурный механизм guard, не разрешение executable callback в public Input.

Общая class acceptance ещё OPEN: concrete activation binding, транзитивные external atomic реализации и полный legacy caller cutover не доказаны этим статическим реестром. Metadata output/bind уже описаны; их прежнее отсутствие не используется как новая находка. Нужны фактические вложенные вызовы и эффекты при реализации. Отдельный serialization/deserialization scope принимается своим планом. Отсутствие новых DAG-нод не мешает конкретизации самостоятельных Pack-контрактов; ноды не придумываются. Порядок источники → evidence → manifest → codec/readers, перенос callers до удаления legacy и отдельный последующий version-name audit не меняются.
