# Pack locations_index — формат и позиционные зависимости

Статическая сверка 2026-11-12. Область — собственный read/admission контракт Pack. Runtime и shared POJO не менялись; миграция внешних callers остаётся у их владельцев. Связь: [роли payload](pack-v2-domain-contract-spec.md#6-роли-payload-сверка-writer--reader--retention-2026-11-12).

## Подтверждённая семантика

`build_locations_index` формирует existing LocationsIndexWire из occupancy winners, пропускает локации без map_x/map_y и материализует map_z=0 при отсутствии исходного значения. Он проверяет membership system_location_type по разрешённому registry при построении. `WorldPackWriter.write_locations_index` записывает его JSON без TileCodec/Zstd. `load_locations_index` читает JSON; legacy render facade при отсутствии файла возвращает пустой индекс. Это не требование к новому read_part: отсутствующий адрес, отсутствующий blob и существующий пустой payload различаются по уже принятому контракту.

`LocationsIndexWire.locations` — список LocationsIndexPin. Pin содержит location_uid, map_x/map_y/map_z, display_name, system_location_type/subtype и system_city_size. В нём нет TerritoryVolume, world_uid или дочерних ArtifactRef. Поэтому storage closure этого payload пуст, а source provenance — отдельная зависимость использования. Нельзя объявлять проверкой payload сравнение world/territory с полями, которых в нём нет. Индекс pins и assembly.locations с materialized terrain имеют разные обязанности; равенство их UID-наборов не установлено и не вводится (L0 pins могут существовать до L2 terrain).

Историческое чтение не проверяет ключи по latest registry: это прямо задано ТЗ Pack в разделе LocationsIndexPin. Existing `overlay_location_pins` — отдельная render-проекция по SQL, сохраняющая длину и порядок. Она не становится частью immutable read_part и не меняет сохранённые bytes версии.

## Порядок locations является смысловыми данными

Цепочка: `SettlementContributor.apply` делает enumerate(ctx.locations_index.locations) и записывает index в WorldMapCellWire.location_pin; при пересечении выбирает меньший index. `render/pack/locationPinOverlay.py::pin_at` возвращает pins[index]; `WorldMapMacroRender.tile_settlement_glyph` использует это разрешение. Owning ТЗ также определяет location_pin как index → locations_index.

Следовательно, canonical codec обязан сохранять порядок locations. Это не множество и не допускающий сортировку список UID. Пример: индекс [A, B], location_pin=0 означает A; замена индекса на [B, A] при неизменном map_tile ref меняет значение той же клетки на B. Одинаковая длина и тот же UID-set не доказывают совместимость. Подтверждено статическим trace, runtime-тест здесь не выполнялся.

Для Pack-owned проверки итогового состава требуется сохранить позиционную связь map_tile ↔ locations_index. Числовой pin должен разрешаться в индекс того же manifest; при inherited map_tile нельзя молча принять переназначение используемой позиции другой локации. Pack не сортирует pins, не перенумеровывает сохранённые L0 клетки и не пересчитывает footprint. Если замена индекса несовместима, producer/DAG должны предъявить согласованный результат обновления зависимых parts; наличие публичного replace_locations_index само по себе не подтверждает совместимость полного candidate.

Точная проверка совместимости входит в final admission полного состояния, а не делает промежуточный write зависимым от немедленного выполнения следующей операции. Новый порядок публичных write-вызовов не вводится. Использованные позиции извлекаются непосредственно из проверенных cells, как конкретизировано ниже; новый зеркальный evidence POJO не нужен. Простое требование «любой новый ref индекса требует пересборки всех tiles» не вводится: изменение неиспользуемой записи не доказывает несовместимость. Совпадение UID в используемой позиции — необходимая проверка этой связи, но не полное доказательство сохранности остальных producer dependencies.

### Конкретный final admission без нового evidence DTO

Проект распределения: `PackPreparationOperation` обеспечивает verified bounded reads/holds, а existing проектный `PackPreparationValidator` выполняет pure сравнения уже материализованных моделей. Assembler не делает IO и не запускает public write methods. Данные: проектный [WorldMapTileWire](pack-read-concrete-models.md) с existing WorldMapCellWire, owning LocationsIndexWire и принятая inherited provenance из final state. Отдельные persisted UsedPins/PinDependency DTO не вводятся.

Два внутренних метода validator, предлагаемых к реализации:

- `validate_location_pin_positions(tile: WorldMapTileWire, index: LocationsIndexWire | None) -> None`: для каждой сохранённой cell пропустить только `location_pin is None`; для остальных требовать strict int, исключая bool, и `0 <= location_pin < len(index.locations)`. При использованном pin отсутствующий index — отказ, а не пустой список. Остальные wire bounds проверяет owning schema.
- `validate_inherited_location_pin_positions(tile: WorldMapTileWire, base_index: LocationsIndexWire | None, index: LocationsIndexWire | None) -> None`: проверить допустимость использованных позиций в обоих индексах и равенство `base_index.locations[p].location_uid == index.locations[p].location_uid`. Метод не сравнивает только counts/UID-set и не перенумеровывает cells.

Наличие/наследование определяется принятой provenance и точной базой, а не одним совпадением hash. Operation читает все необходимые map_tile parts конечного state, включая inherited; отсутствие изменённого tile в очереди writes не исключает его из проверки. Индекс новой версии берётся только из того же final state; base index — из проверенной pinned base. При утрате доступности базы нельзя заменить её latest индексом. Если tiles не содержат используемых pins, отсутствие index не нарушает именно эту позиционную проверку; прочие scope/coverage требования сохраняются.

Локальный набор использованных p можно дедуплицировать для сравнений, но не сохранять как вторую authority и не использовать как доказательство producer footprint. Новый tile обязан пройти range checks и согласованный provenance admission относительно нового индекса; отсутствие inherited сравнения не доказывает правильность его генерации. Неизменённый UID при изменённых координатах/type/size тоже не закрывает producer dependencies. Pack не пересчитывает footprint и не запускает генератор для проверки.

Примеры приёмки: inherited pin=0 и [A,B]→[B,A] — отказ; [A,B]→[A,C] при использовании только 0 проходит позиционный check, но не освобождается от остальных проверок; отрицательный/out-of-range/bool pin — отказ; удаление index при used pin — отказ; отсутствующий payload заявленного index — storage failure, не отсутствие part. Existing render `pin_at` возвращает None для out-of-range; это fallback отображения, не правило final admission. Отказ оформляется согласованным final-prepare error transport, не новым публичным DTO и не подменой его read-part refusal.

Дополнительная статическая сверка 2026-11-13: `WorldMapCellWire.location_pin` имеет default None, а `locationPinOverlay.pin_at` разрешает числовую позицию напрямую через pins[index]. Поэтому pin=0 — полноценная ссылка, а не falsy-признак отсутствия; пропускается только None. Граничные примеры реализации: pin=0 при пустом/отсутствующем индексе — отказ; None при отсутствии индекса проходит именно позиционную проверку; pin=len(index.locations)-1 допустим, pin=len(index.locations) — отказ. При нескольких неверных cells независимые диагностики сохраняют исходный порядок и позиции cells; локальная дедупликация используемых pins не должна терять привязку ошибок. Повторы UID в индексе не превращаются в запрет: контракт сравнивает реально используемые позиции, остальные producer dependencies проверяются отдельно.

Это PROJECT методов, не изменение runtime. Конкретизация закрывает способ получения positions для локальной проверки; implementation tests, bounded reads/retention и общий provenance binding ещё требуют реализации. Порядок публичных writes не меняется, промежуточное состояние может быть неполным, итог проверяется перед stage/READY.

## Конкретизация decoder (проект, 2026-11-13)

`LocationsIndexDecoder` получает при сборке binding существующий `DecodeLimits`; порт `decode(payload: bytes, format_version: int) -> LocationsIndexWire`, `validate(value: LocationsIndexWire) -> LocationsIndexWire`. Используются проектные storage/read descriptors из [roster](pack-payload-binding-roster.md), версия storage 1. Это JSON UTF-8 без TileCodec header, Zstd и автоматического распознавания другого формата. Descriptor хранит bytes, decoder возвращает owning модель; переписывать сохранённый artifact ради typed read не требуется.

Ответственность decoder: проверить версию, byte budget до parse, ограничения nodes/depth/items при разборе и структуру root/pins. `validate` применяет тот же профиль проверки, включая вложенные значения, а не доверяет одному наличию frozen-экземпляра. Целевое `locations: tuple[LocationsIndexPin, ...]` объявляется в общей модели, без второго Pack POJO. Decoder не читает SQL, latest registry, manifest или Source, не запускает occupancy и не выполняет overlay. Такой вызов либо сортировка/дедупликация pins — критерий отказа в приёмке его ответственности.

**Сохранение текущей семантики.** Root `{}` использует owning default пустого locations, как и явный `{"locations": []}`. Пустые bytes, JSON null и повреждённый JSON не являются пустым индексом. Для pin обязательны location_uid/map_x/map_y; отсутствие map_z даёт 0, nullable поля сохраняют owning defaults. Decoder не подставляет map_z=0 вместо явно недопустимого null: подстановка producer для исходного NamedLocation — отдельный этап. Существующие преобразования полей shared модели не отменяются без отдельного решения. Структурная строгость к неизвестным полям и immutable коллекция не должны скрыто менять defaults или допустимые значения известных полей.

В просмотренной модели нет проверки уникальности UID либо координат. Список сохраняет повторы и исходные позиции: reader membership может строить frozenset UID, но это отдельная проекция, не формат хранения. Не добавлять запрет повторов, преобразование списка в dict по UID, сортировку или фильтрацию по occupancy внутри decoder. Исторические registry keys проверяются по owning типу, без проверки membership в текущем registry; наличие custom key не запускает builder. Новые ограничения непустоты UID или диапазонов координат не выводятся из имени поля.

**Граница локальной и составной проверки.** Decoder индекса не имеет map_tile и не доказывает корректность location_pin. Final admission читает части того же candidate и проверяет используемые позиции; сравнение inherited tile с базовым индексом требует pinned base, а не latest. Эти чтения учитываются общим read budget. Список использованных позиций можно получить из уже декодированных клеток; отдельный публичный зеркальный evidence POJO не нужен. При этом этот локальный проход не заменяет проверку producer dependencies и не делает совпадение UID достаточным доказательством их неизменности. Точный внутренний проход и удержание base должны быть предъявлены при реализации final admission; порядок публичных write-операций не меняется.

Ошибки используют общий контракт Pack: неподдерживаемые descriptor/version — `CONTRACT_MISMATCH`, повреждённый JSON или нарушение принятой схемы — `INVALID_PAYLOAD`, превышение лимитов — `BUDGET_EXCEEDED`. Ошибка чтения blob и отсутствие адреса остаются отдельными исходами публичного read; decoder не возвращает пустой индекс при отказе. Storage closure этого leaf пуст; provenance retention проверяется отдельно.

Дополнительная приёмка: `{}` и явный пустой список; отсутствие обязательного поля pin; пропущенный map_z против явного null; повторяющиеся UID/координаты с сохранением позиций; ограничение структуры при допустимом размере bytes; отказ от unknown fields без потери значений; одинаковые результаты decode/validate/read/prepare. Проверки совместимости locations_index с map_tile выполняются отдельно на полном candidate. Это проектные требования, runtime-тесты не выполнялись.

Сигнатура общего порта использует owning `FormatVersion`; `int` в описании decoder выше — сокращённая запись, не отдельный тип версии. Общие требования decode/validate и остаток typed JSON budget signal сведены в [roster](pack-payload-binding-roster.md#сверка-общего-порта-и-профилей-2026-11-13).

## Read binding и предел локальной работы

Переиспользовать LocationsIndexWire/LocationsIndexPin, не добавлять вторые frozen-модели с теми же полями. Existing root frozen содержит mutable list, nested extra=ignore допускает потерю неизвестных полей; это ещё не deep immutable strict contract. Миграция общей модели/consumers выполняется отдельным согласованным срезом; сейчас не менять интегрированные методы других доменов и не ослаблять обещание immutable read.

Storage — BLOB bytes binding, typed read T — existing owning LocationsIndexWire после принятой адаптации. Перед JSON parse применяется explicit byte budget; encoded IO учитывается PackPartReadBudget, memory expansion проверяется при приёмке decoder. Декомпрессия этому формату не нужна. Descriptors и порт decoder конкретизированы в проекте; их runtime-реализация, concrete typed errors и composition registration пока не предъявлены; leaf closure сама их не заменяет.

Проверки: round-trip сохраняет порядок и значения pins; reorder меняет fingerprint/digest; same count/UID-set с другой индексацией не проходит как доказательство совместимости inherited L0; empty payload отличается от absent и missing blob; повреждение JSON и unknown fields не становятся пустым индексом; исторический custom registry key читается без latest membership lookup; returned value не требует IO после закрытия guard. Список фиксирует требования, не успешные тесты. Полная приёмка binding остаётся OPEN.
