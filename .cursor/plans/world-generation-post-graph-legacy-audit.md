# LEGACY-POST — поиск оставшихся legacy-путей генерации мира

**Статус: отложен до окончания основных работ.** Владелец аудита — координатор [общего графа](./world-generation-plan-dependency-graph.md). При закрытии основной очереди координатор фиксирует итоговую ревизию, выполненные переключения и явно вынесенные за её пределы работы. Это основание для запуска LEGACY-POST. GRAPH-AC означает согласование карты; для запуска нужна запись о фактическом завершении работ в её согласованном объёме.

| Шаг | Вход | Результат |
|---|---|---|
| L1. Поиск | Итоговая ревизия и перечень заменённых контрактов из owning-планов | Сверить известные локальные реестры, включая GEO I9.3, с итоговым checkout. Искать по прежним символам, import paths, wire IDs, версиям и точкам выбора реализации. Проверить aliases, re-exports, регистрации, API/DAG entrypoints, readers/writers, fallback, fixtures и тестовые миры. |
| L2. Проверка достижимости | Кандидаты L1 | Для каждого указать ссылку на определение, замену, owner и путь от реального caller. Для пути без найденных callers записать проверенные точки регистрации, динамического выбора и загрузки данных. Отдельно отметить зависимость только со стороны тестов. |
| L3. Передача владельцам | Проверенный реестр L2 | Для каждой записи предложить удаление, миграцию потребителя либо временное сохранение с конкретным обязательством и условием удаления. Для устаревших тестовых миров указать способ пересоздания по новому контракту. |

**Критерий завершения аудита.** Представлены ревизия, покрытые области, поисковые ключи, реестр с доказательствами и открытые вопросы по владельцам. Если кандидатов в области нет, приложить результаты поиска и проверки entrypoints. На этом остановиться и предъявить отчёт пользователю. Правки кода, удаление путей и миграции выполняются отдельными заданиями владельцев по [правилу legacy](../rules/legacy-folder.mdc).
