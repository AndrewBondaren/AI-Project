# Snapshot → Source: состояние authored apply binding

2026-11-14. Адресная статическая сверка Source revision storage §5. Без нового API, DTO или протокола. Статусы provisional для текущей разработки; перед freeze/implement-plan перечитать актуальные файлы.

1. **Принятый общий контракт существует, конкретного authored Terrain/Source binding пока нет.** [Snapshot ТЗ](../../docs/tz_world_snapshot.md), §«Контракты ядра Snapshot — freeze шага 2», §«Snapshot.apply, результаты и порядок проверок»: IWorldSnapshotApply.apply(PatchSet[S]) → SnapshotApplyResult; borrowed handler validation/apply и общая publication transaction. Freeze принят 2026-10-30. Runtime требует gameplay_started и pack; это не готовый pregame authored mutation entry.

2. **Реализация частичная.** [applyPort.py](../../backend/app/application/worldSnapshot/contracts/applyPort.py) содержит Protocol. [context.py](../../backend/app/application/worldSnapshot/contracts/context.py) и [commitScope.py](../../backend/app/application/worldSnapshot/contracts/commitScope.py) содержат internal context и IDomainCommitBinding.bind(scope). [WorldSnapshotService](../../backend/app/application/worldSnapshot/service/worldSnapshotService.py) реализует внутренние _apply_to_target/_append_metadata/_append_metadata_and_handoff, но публичного apply здесь нет. [Owning-план](world-domain-patches-snapshots.md), приёмки 4D2 player CAS, metadata и holder handoff: подтверждён scoped world/player publication; публичный apply, terminal/retry и production composition не входят в эту evidence.

3. **Разделение существующих механизмов:** domain handlers выполняют свои scoped append effects; Snapshot собирает metadata/refs, делает handoff и world/player CAS; commit принадлежит publication coordinator. Existing WorldPublicationRef — applied publication identity/pack+snapshot head, не Source latest revision. Принятого mapping authored Source revision transition/head → applied Terrain World state в проверенном Snapshot freeze/коде не найдено. Нельзя считать max Source seq applied head или использовать WorldService._save/repo.update как append-only scoped writer.

4. **На что Source storage может опереться:** на accepted capability/atomicity требования и immutable refs ядра. На конкретный writer authored Terrain, конкретный pregame set handler или completed Source mutation lifecycle — пока нельзя. Source storage может описать свою append-only index ответственность, но не объявлять согласованную атомарность с applied World state до принятого конкретного binding. SourceMutationAttemptRunner/grant/recovery предложения в source-mutation-artifacts-publication-response-2026-11-13.md не являются существующим Snapshot.apply по аналогии и не закрывают этот gap.

5. **Что пересверить перед freeze:** текущие 4D2/terminal-retry статусы; [public integration plan](snapshot-public-contracts-dag-integration.md) и [public method proposal](snapshot-public-methods-contract.md) (предложения, не готовый runtime); актуальные SnapshotApplyContext/handler/transaction signatures; Source revision storage и Terrain writer dossier; разрешённые origin/authority contracts Pack отдельно. Новые границы пользователя: public методы через DAG; сейчас уточняются Source/Pack/Cache/Snapshot; остальные domains сохраняются v1 без адаптеров. Эти рамки не вводят новый authored writer сами по себе.

Вывод: **общий runtime Snapshot freeze — принят; scoped core — частично реализован и проверен; конкретный authored Terrain/Source set binding — отсутствует как принятый готовый контракт.** Не проектировался заново этим ответом. Runtime tests не запускались. Общий Source план/код не изменялись.
