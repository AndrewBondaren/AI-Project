# SN-TIME-READ · передача принятого состояния из Snapshot в Time

Семантика API согласована пользователем, 8 ноября 2026. Gate T4 остаётся OPEN до интеграционной проверки. Единица закрепления — сохранённая полная WorldPublicationRef P. Проверка P после commit Q должна работать в заново открытой транзакции. Держать исходное соединение от P до Q недостаточно.

## Что сегодня происходит при вызове

1. `TimeReader.read_current(CurrentTimeRead(expected=P))` передаёт тот же request в `source.read_current`. Reader не открывает транзакцию. Производственная цепочка здесь обрывается. На стороне Snapshot `SqlitePublicationCommitStore.read_scope()` открывает read transaction, а при переданной capability проверяет её в registry и возвращает тот же scope. `world.read(P.world_uid, scope=r)` вызывает _latest, упорядоченный по publication_seq. После Q он вернёт Q. В том же адаптере _by_id уже реконструирует ref по publication_id и проверяет сохранённые связи. Этот private helper пока не является публичным exact-read портом. [Time reader](../../backend/app/application/time/reads/reader.py) · [scope](../../backend/app/db/repositories/sqlite/snapshotCore/commitScope.py) · [publication store](../../backend/app/db/repositories/sqlite/snapshotCore/publications/worldPublicationStore.py)
2. `TimeReader.read_historical(HistoricalTimeRead(snapshot=S))` аналогично делегирует источнику. SQLite history.read(S, scope=r) уже ищет world row по snapshot_id, декодирует с ожидаемой полной ref, проверяет operation/parent и возвращает envelope либо None при отсутствии row. Metadata builder при записи перенёс effective state_refs из принятой базы, заменив изменённые секции. Поэтому writer snapshot в state_ref может быть старше запрошенного S. Round-trip и наследование подтверждены тестами history. Значение часов этот reader не загружает. Тест Time test_pinned_reads использует подставленный source. [History](../../backend/app/db/repositories/sqlite/snapshotCore/history/snapshotHistoryStore.py) · [builder](../../backend/app/application/worldSnapshot/service/snapshotMetadataBuilder.py) · [history tests](../../backend/tests/snapshotCore/storage/publication/test_history.py) · [Time tests](../../backend/tests/time/test_time_core.py)

## Решение о семантике публикации

§11 Time обещает конфликт при повторном fresh current(P) после Q. Snapshot требует повторяемого чтения P после Q. Согласовано сохранить read_current(expected=P) как проверку актуальности и добавить read_pinned(P) в TimeReader и ITimeReadSource. Оба пути используют один resolver. Current сначала читает observed в том же scope, затем при равенстве работает с уже проверенной P. Pinned загружает принятую P по identity независимо от latest. Для advance остаётся current.

## Snapshot → Time, предлагаемые операции

Имена новых файлов относительно backend/app. Snapshot владеет read capability и адресацией. Time владеет orchestration своего порта, payload и capture. На каждый публичный вызов production source входит один раз в предоставленный Snapshot контекст `async with scopes.read_scope() as r`, передаёт r каждому IO и завершает сборку результата внутри блока. Capability не сохраняется между вызовами.

## Границы отказа

- Pregame/bootstrap даёт TimeStateUnavailable(world_uid, CLOCK_UNINITIALIZED). Начатая headless P требует сохранённый initial binding именно P, даже если его ожидаемая координата равна нулю. Унаследованный head требует binding именно P с точкой active_timeline_id дочерней ветки (world_uid остаётся прежним). Если binding отсутствует, вернуть SOURCE_UNRESOLVED. Сегодня SQLite проверяет runtime transition как SNAPSHOT_APPLY с прежней active timeline. Унаследованный head проверяется на уровне контракта с принятой фикстурой до появления branch writer.
- Для current при отсутствии мира — WORLD_MISSING (нужно различать подтверждённое отсутствие мира и повреждённую publication chain). Если expected и observed имеют разные активные timeline и requested timeline задана — TimeInactiveTimeline(requested, active). Иное несовпадение полных refs — TimePublicationConflict(expected, observed). Для pinned отсутствующая пара или несовпадение с реконструированной P → SOURCE_UNRESOLVED. Никогда не читать head из непроверенного request.
- Для исторического отсутствующего S — SNAPSHOT_MISSING. Для обычной принятой P с исчезнувшим обязательным head, отсутствующей clock section, неподдерживаемого формата либо отсутствующего payload — SOURCE_UNRESOLVED, если storage вернул штатное отсутствие. Все TimeStateUnavailable содержат world_uid запроса. Для historical отсутствие обязательной секции/payload также SOURCE_UNRESOLVED.
- Чужой мир в head запрещён. Обычный section ref должен адресовать world snapshot требуемого мира и timeline. Чужая timeline в section/point, подмена ref того же типа, чужой world/player envelope и нарушения relation/checksum в сохранённых данных являются integrity fault. Существующий storage exception пробрасывается, при нарушении инварианта адаптера — PublicationInfrastructureError. Никакого rebind точки при чтении. Исторический S неактивной timeline допустим при полном совпадении владельца. Cancellation выходит из scope с исходным исключением.

## Приёмка и граница первого среза

Минимальный end-to-end тест для T4 в backend/tests/time/test_snapshot_read_source.py использует файловый SQLite, общий coordinator, production source через TimeReader и реальные scoped payload readers. Fixture создаёт принятые строки и metadata с корректными FK/operation evidence в transaction. T5 handler тесту не требуется.

1. Зафиксировать начатую P с head=None и initial point p. Прочитать P, сохранить полную ref и закрыть scope.
2. Вторым соединением принять Q с head=S, clock state_ref R и point q ≠ p. Завершить commit. В свежих scopes проверить read_pinned(P) == TimeCapture(P,p), read_pinned(Q) == TimeCapture(Q,q), read_historical(S) == HistoricalTimeCapture(S,q). В том же тесте проверить current(P) == conflict(P,Q), current(Q) == TimeCapture(Q,q).
3. Добавить snapshot без clock change и проверить прежний R из его metadata. Для inherited head проверить адрес P дочерней timeline и отсутствие чтения родительского payload. Негативные параметры — неподходящий world/timeline, пропущенный binding, отсутствующие S/section/payload. Spy на scoped IO проверяет одинаковую capability внутри вызова. Ни один успех не зависит от кэша предыдущего запроса.

На новом пути нет CalendarProjector и emitter. TL-B PROJECT уже наблюдает projector.project в candidate.projected при World preparation. READ_CURRENT и READ_HISTORICAL остаются отдельными будущими binding у фактического caller. Проверка — чтение P/Q/S даёт ноль PROJECT и ни одного вызова project, существующие тесты PROJECT сохраняют прежние количества событий. [Отчёт TL-B](./time-log-project-report.md)
