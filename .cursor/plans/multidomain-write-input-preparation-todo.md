# Подготовка входов совместной записи доменов

Дата: 2026-11-20. Статус: **TODO — отдельный план проектирования**, создан по решению пользователя. Реализация не разрешена. Координатор междоменных контрактов — Between domain operations.

## Цель и граница

Спроектировать вышестоящий процесс, который подготавливает согласованные входы общей записи для Time и других участвующих доменов. Состав остальных доменов и владелец сценария — TODO; обязательное участие любого конкретного домена не назначается.

Этот процесс предшествует рассматриваемой операции записи. IC-1 описывает выполнение при уже переданных входах: Time.prepare_section → native section → assemble_patch_set → Snapshot.apply → receipt. Источники operation_id, исходного состояния и параметров изменения не являются блокерами локального IC-1. Требования к этим значениям, их проверка и поведение при несовпадении остаются в контракте записи.

Подготовка TimeAdvanceProposal через prepare_advance может относиться к этому верхнему процессу; обязательный вызов prepare_advance внутри записи не вводится. Порядок верхней цепочки и NodeId пока не утверждены. Gameplay и генераторы не проектируются в рамках текущей работы.

По решению пользователя 2026-11-20 producer готовой exact-Q Time записи не блокирует локальный H3 на готовых данных. До готовности initial/branch-point сценария необходимо определить владельца producer и точный Output → TimePublicationRow mapping, обеспечить atomic visibility публикации Q и immutable PublicationTimeState для её активного timeline. Time владеет admission/representation; владелец публикации и transaction composition определяется при согласовании. Требуется отдельно сверить создание row с принятым initial artifact/start protocol: скрытого artifact→row materialize внутри Snapshot/H3 не разрешено. Чужой timeline, initial ancestor, zero/fallback не заменяют необходимое состояние. H3 только читает/проверяет его; missing даёт REQUIRED_STATE_MISSING. Producer, преобразования времени и новые публичные операции этим TODO не утверждаются. Отсутствие producer блокирует соответствующий верхний сценарий, не принятый локальный контракт чтения/записи.

## Критерии приёмки

Для каждого перехода определены публичные цели, именованные Input/Output/Error, владельцы полей, проверки, эффекты и гарантии. Доменная логика не переносится в DAG; оркестрация распределена по уровням, нижние ноды имеют одну ответственность. Применяются все обязательные критерии из dag-generator-interface.mdc и правило interdomain-contract-coordination.mdc. Неизменные принятые контракты записи не переоткрываются; предлагаемое изменение границы согласуется отдельно.

Проектирование и доказательства реализации учитываются отдельно. Отсутствие этой верхней цепочки не препятствует приёмке контракта записи на готовых входах.
