## Миграция тестовых миров и диагностических fixtures

В `tests/geo1/native_final/test_facts.py:NativeFinalTests.setUp` общий `tests.geo1.fine_water.test_fill.basin` задаёт LAKE и уровень 0; `physical_inputs` берёт default_water_level=0. В `waterClassifier.py:classify_components` крупнейшая компонента на этом уровне получает OCEAN. Даже после смены уровня действует порог inland sea: для 16 клеток на 32×32 доля 0,015625 выше дефолтных 0,01. Для сценария, которому нужно именно физическое озеро, задавать политику в захваченном physical input до decisions/fill. Проверенная проба с теми же 4×4 клетками, `default_water_level=-1` и `seas.inland_sea_min_area_fraction=0.5` вернула тело `lake` вида LAKE и пустые diagnostics. Для других размеров подобрать порог выше фактической доли компоненты. Сценарий mismatch должен намеренно сохранить расхождение и проверить typed FALLBACK. Такая настройка fixture применима только там, где цель сценария — обычное озеро.

40 прямых вызовов в тестовом коде — отдельный срез миграции. Например, `integration/support/pipeline.py:placement_plan` заранее строит unresolved decision через FieldPathError ещё до resolve, что даёт девять записей. Для миров с failed support собирать решение через действующие Policy support/binding и resolver, задавать конкретную причину домена с проверенным полем; для заранее построенных upstream diagnostics использовать конкретный тип владельца, исходную disposition и подписанный envelope. В тестах codec сохранять тип и данные причины после decode. В тестах collector выбирать тип из admitted этого владельца. Для отсутствующего support различать waiting и failed. Сами по себе ошибки общего setUp не доказывают дефект последующих алгоритмов.

## Единственный assertion · Water Input / Hydrology

Изолированный запуск `tests.geo1.contracts.cascade.test_legacy.LegacyGenerationTests.test_shared_wire_engine_uses_the_owning_before_validator` воспроизводит failure на строке 139. Проверки миграции old=False, отсутствия ошибок для валидного объекта и отказа UnresolvedModelError при конфликте уже прошли. Прямой before-validator в `app/dataModel/hydrology/generation/legacySettings.py` выдаёт PydanticCustomError с GENERATION_SETTINGS_CONFLICT. Общая граница `app/application/jsonValidation/resolution/wireIssues.py:_schema_issue` переводит пользовательский тип в JsonValidationCode.VALIDATION_ERROR.

По G2-P требуется сохранять authored presence, строгий bool и явный отказ при противоречии old/new. По J2(C) конкретную причину GENERATION_SETTINGS_CONFLICT должен переносить Water Input через доменную ошибку Hydrology; добавление этого значения в JsonValidationCode нарушает распределение ответственности. Нынешнее ожидание строки на внешнем ctx.errors[-1].code фиксирует старую форму передачи. Решение J2 прямо отмечает этот временный красный тест. В срезе Water Input проверять отказ и тип/код конкретной причины на wire-границе для всех трёх legacy flags, сохранив прямую проверку нормализатора. Подмена ожидания на общий VALIDATION_ERROR как конечный критерий потеряла бы различимость конфликта. [ТЗ cascade, G2-P](../../docs/tz_cascade_context.md) · [ERROR-CONTRACTS, решение J2(C)](error-contracts-1.md)
