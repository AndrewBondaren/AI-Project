# Implement plan

Эта команда = явная просьба **писать код** в скоупе указанного плана. Workspace-правило «код только по просьбе» на этот скоуп снято. Коммит, DAG, backend, `0002_*.sql` — нет, пока мастер не сказал отдельно.

## Вход

Путь плана — текст после `/implement-plan`, иначе открытый `*.md` в `.cursor/plans/`, иначе спросить одним вопросом. Не гадать между несколькими планами.

Прочитать **целиком**: план, затем SoT-файлы, на которые он ссылается (`docs/tz_*.md` и указанные §). Алгоритм из ТЗ не пересказывать в код-комментарии и не копировать таблицы резолва в генератор.

## Истина

| Вопрос | Где ответ |
|---|---|
| Алгоритм, инварианты, семантика полей | доменное ТЗ |
| Порядок поставки, слои, файлы, out-of-scope | план |
| Defaults, wire-ключи, `canonical_defaults` | `backend/app/dataModel/` |
| Расхождение план ↔ ТЗ | **стоп**, один вопрос мастеру; не «чинить ТЗ заодно» |

План — не второе ТЗ. Если план велит литерал, а POJO уже держит то же значение — читать POJO.

## Перед кодом

1. Сверить план с **текущим кодом** (план может отставать: слой уже закрыт). Не делать работу дважды.
2. Взять из плана: scope / не в план; слои A→…; «не трогать»; дырки SoT; приёмку.
3. Дырка SoT в текущем слое → не импровизировать геометрию/`system_*`/дефолты. Спросить.
4. Скелет контрактов слоя (типы, сигнатуры, writer) **до** наполнения одного прохода. Не слайс «только рамка без packing», если план запрещает.

## Жёсткие запреты

- Не стартовать backend (`python start.py`, `uvicorn`, `npm run backend`).
- Не менять `application/engine/nodes/` (DAG).
- Не создавать `0002_*.sql`. SQL-схема — только `0001_initial.sql` + sync `db/models/`, и только если план/мастер явно просит persist.
- Не трогать файлы/темы из «не в план» / «не трогать».
- Не предлагать interim `scene_narration` / vertical slice игрока.
- Не коммитить и не пушить.
- Генератор = materialize данных. Не LLM payload, не `display_name` для чата, не persist внутри generator.
- Массовый SQL — только `app.db.bulkSql`.

## Как кодить

- Слои плана **по порядку**. Следующий слой — после закрытия предыдущего (контракт + вызов, не «файл создан»).
- Новые builtin-значения — в POJO, тонкий resolve рядом с моделью, без `_DEFAULT_*` и `dict.get` по wire-ключам модели.
- Runtime dataclass (`CitySkeleton` и аналоги) — зеркало имён POJO, не третий набор полей.
- Логи — sink из плана / `tz_logging.md`, не новый `getLogger` в обход `loggingConfig`.
- Тесты — если план просит или сломался существующий API; не плодить пирамиду «заодно».
- ТЗ и сам план **не править**, пока мастер не сказал «правь». Исключение: ложь в плане после закрытого слоя — одна короткая пометка статуса, если мастер это уже разрешал в этой сессии.

## Стоп-кадры (спросить, не выдумывать)

- Пункт плана помечен ⬜ / CONN-PACK / «открыт» / TODO вне текущего слоя.
- Нужен writer клеток / SQL / DAG, а план говорит «не этот план».
- Приёмка требует живой сервер — описать, **что запустить мастеру**, не поднимать самому.

## Отчёт после каждого слоя и в конце

Кратко, без дампа алгоритма:

- что сделано (файлы / контракт);
- что уже было в коде до команды;
- что осталось по плану;
- что сознательно не тронуто;
- как мастеру проверить (unittest / `debug_settlement.py` / HTTP) — без старта сервера агентом.
