# Изменения кода

При приёмке плана любого домена применяй [обязательные критерии DAG](.cursor/rules/dag-generator-interface.mdc#обязательная-приёмка-плана-любого-домена). Любое нарушение одного из трёх запретов означает отказ в приёмке.

Для любой задачи, требующей создания, изменения или удаления кода в этом репозитории, пользователь предписывает применять скилл `implement-plan`. Это постоянное указание действует и при работе через другие скиллы и подагентов. Вводить команду `/implement-plan` в каждом запросе не требуется.

Перед первой правкой прочитай [.agents/skills/implement-plan/SKILL.md](.agents/skills/implement-plan/SKILL.md) и следуй его инструкциям. Если скилл недоступен, остановись до записи. Любое добавление или иное изменение кода в обход скилла считается несанкционированным.

Каждую ручную правку вноси инструментом `apply_patch`. Для задачи без отдельного файла плана объём работы задаёт запрос пользователя. Обсуждение и чтение кода сами по себе не разрешают правки.

Прежде чем объявлять правку заблокированной из-за прав или просить повышения доступа, отправь реальный патч по задаче через встроенный инструмент `apply_patch`. Просить повышения доступа можно только после фактического отказа в записи из-за прав. В запросе укажи путь к файлу и точный текст отказа инструмента. Профиль `read-only` сам по себе такого отказа не доказывает. При несовпадении контекста перечитай файл и исправь патч. Запрещено обходить инструмент прямой записью или запуском patch CLI через PowerShell, Python или другую оболочку.
